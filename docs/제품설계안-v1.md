# AX MVP Factory OS — 제품 설계안 v1

> 업종 맞춤형 AX MVP 설계·제작 운영 시스템 (내부 운영 OS, SaaS 아님)
> 작성일: 2026-07-19 · 상태: 승인 대기 (승인 전 코드 작성 금지)

## 1. 핵심 목적 (한 문장)

"고객사 정보와 현장 설문을 입력하면, 업종 맞춤 AX MVP의 진단→설계→개발 프롬프트→단계 관리→기관 증빙까지 하나의 표준 파이프라인으로 뽑아내고, 프로젝트가 끝날 때마다 다음 설계가 더 정확해지는 내부 운영 OS."

핵심은 '자동 개발 도구'가 아니라 **'설계 표준화 + 품질 게이트 + 데이터 축적'**.

## 2. 핵심 사용자와 사용 시나리오

| 사용자 | 역할 | 접근 |
|---|---|---|
| 대표(owner) | 전체 운영·판정 확정·산출물 승인 | 로그인 |
| 내부 직원(staff) | 프로젝트 진행·설문 발송·기록 | 로그인 |
| 고객 대표자(respondent) | 경영 관점 설문 응답 | 비로그인 토큰 링크 |
| 고객 현장 담당자(respondent) | 실무 관점 설문 응답 | 비로그인 토큰 링크(별도) |

표준 시나리오: 고객사 등록 → 업종 선택 → 설문 자동 조립(공통+업종 모듈) → 대표자용/현장용 링크 2개 발송 → 응답 수집·자동 요약 → AX 적합성 판정(근거 표시) → 판정 확정(수동 오버라이드 가능) → 템플릿 조합 추천 → 기능명세·Claude Code 프롬프트·기관자료 초안 생성 → Stage-Gate로 단계 진행·테스트 기록 → 자금 신청·평가 결과 기록 → 데이터 축적.

## 3. 해결하려는 가장 큰 문제

1. 제로베이스 반복 — 고객마다 설문·설계·프롬프트·문서를 처음부터 다시 만드는 비용
2. 범위 폭주 — 고객 요구가 늘며 MVP가 커지는 것을 막을 객관적 기준 부재
3. 판단 근거 부재 — "이 기업에 AX를 만들어야 하는가"를 감으로 결정
4. 데이터 증발 — 기관 평가에서 무엇이 통했는지가 머릿속에만 남음

## 4. 1차 MVP의 정확한 범위 (In)

- 프로젝트 관리: 고객사·프로젝트 등록, 업종 선택, Stage 0~7 관리, 단계별 체크리스트·테스트 기록, 타임라인
- 설문 시스템: 질문은행(공통+업종 모듈) → 설문 조립 → 토큰 링크 발급(대표자/현장 역할 분리) → 응답 화면(단일/복수/예아니오/5점/숫자/금액/주관식/조건부/"잘 모르겠습니다", 자동 저장, 진행률, 모바일) → 제출
- 분석·판정: 응답 요약(미응답·모순·강조), AX 적합성 점수+7종 판정(근거 표시, 수동 확정), 개선 업무 후보, 템플릿 조합 추천
- 산출물 생성(룰 기반 치환): ①AX 진단보고서 ②MVP 기능명세(화면·DB 초안 포함) ③Claude Code 개발 프롬프트 ④기관 설명자료 초안 ⑤테스트 체크리스트
- 데이터 축적: 자금 신청·결과 기록 + 신청 시점 MVP 스냅샷

## 5. 제외 (Out — 1차)

- 코드 자동 생성·자동 배포 (프롬프트 생성까지만)
- 멀티테넌트·결제·SaaS화 (DB에 org_id 컬럼만 예약)
- 파일 업로드·표 반복 입력·업무 순서 정렬 문항 (1.5차)
- AI API 자동 호출 (생성기는 룰 기반, AI는 수동 트리거로 2차)
- 카톡·이메일 자동 알림 (링크 수동 전달)
- 통계 분석·경향 차트 (표본 10건+ 이후)
- 고객용 포털(설문 외 화면)

## 6. 단계별 운영 프로세스

Stage 0~7 × 상태 12종 (원안 채택). 각 단계 레코드: 목적/상태/시작·완료일/담당/고객 담당/필요 자료/완료 조건/테스트/고객 확인/보류 사유/위험/산출물/커뮤니케이션 로그/다음 액션. 다음 단계 진행 = 게이트 조건 충족 + 수동 승인 (자동 진행 없음).

## 7. 설문 시스템 구조

```
question_bank (질문은행, 버전 관리)
   ├─ 공통 코어 (섹션 A~H)
   └─ 업종 모듈 (industry_modules)
        ↓ 조립
surveys (프로젝트별 설문 스냅샷 — 질문 원문 고정 저장)
        ↓ 발급
survey_links (토큰, 역할: 대표자/현장, 만료일)
        ↓ 응답
survey_sessions (자동저장·진행률) + survey_answers (문항별, 질문 스냅샷 포함)
        ↓ 분석
response summary → assessments (판정)
```

- 질문 스냅샷 저장 필수: 질문은행 수정 후에도 과거 응답 의미 보존
- 조건부 분기: `condition: {question_key, operator, value}` JSON 선언
- 대표자/현장 링크는 같은 설문의 역할별 부분집합, 응답 비교 뷰 제공

## 8. 공통/업종 특화 질문 분리

- 질문 태그: `scope(common|industry)` + `industry_code` + `section(A~H)` + `role(대표자|현장|공통)`
- 조립: 공통 코어(60~70%) 자동 포함 + 업종 모듈 병합 + 프로젝트별 문항 추가/제외
- 초기 콘텐츠: 공통 60문항(대표자 25/현장 25/공통 10) + 업종 모듈 3종 × 20문항. 업종 3종으로 시작

## 9. AX 적합성 점수 초안

6축 점수 + 2플래그 + 규칙 기반 판정 (가중합 단독 판정 금지):

| 축 | 소스 | 가중치 |
|---|---|---|
| ① 업무 반복성·명확도 | B | 25% |
| ② 낭비 규모(정량) | C (월 낭비시간×인건비) | 20% |
| ③ 데이터 준비도 | D | 20% |
| ④ 도입 의지·실행력 | G (대표·현장 각각) | 25% |
| ⑤ 자금 연계성 | A | 10% |
| ⑥ AI 필요 형태 | F → 유형 판정(규칙/AI/고급) | — |
| 🚩 전문가 위험 | 빨간 영역 감지 | — |
| 🚩 데이터 신뢰도 | 미응답+모름 30%↑ | — |

판정 규칙: ④<40→"도입 의지 부족" / 🚩신뢰도→"판정 보류+추가 인터뷰 질문" / ③<30→"데이터 부족 보류" 또는 "진단·문서 자동화부터" / 총점70+&AI신호→"AX 결합형 적극 추천" / 50~70→"간단한 업무자동화만" / ⑤만 높음→"자금조달 컨설팅만" / 🚩위험→"전문가 검토 후 진행". 임계값은 설정에서 조정. 최종 판정은 사람이 확정, 시스템↔수동 판정 차이는 사유 기록(학습 데이터).

## 10. 표준 MVP 템플릿 구조

8종(원안) = 공통 모듈 조합 + 업종 조정 포인트 선언(입력 항목/업무 순서/계산식/판정 기준/AI 프롬프트/보고서 목차/KPI/전문가 확인 항목). 추천: 설문 신호 → 템플릿별 매칭 점수 → "일정관리형 60% + 문서생성형 40%" 식 조합·비율·근거 출력.

## 11. Stage-Gate 구조

- projects.current_stage(0~7) + current_level(0~5) + target_level 분리 표기
- 단계 통과 = 게이트 체크리스트 전 항목 판정 + 승인 버튼 → 다음 단계 레코드 생성
- 레벨 상승 게이트(의지·자료·실사용·테스트·KPI·전문가·계약·자금)는 별도 체크리스트
- 보류·중단 사유 필수 → 대시보드 위험/지연 목록 자동 반영

## 12. 테스트와 통과 기준

test_records: 단계별 테스트 항목(시드) + 판정 5종(통과/조건부/재검사/보류/중단) + 비고 + 판정자·일시. 조건부 통과는 조건 필수 기록, 재검사는 이력 보존.

## 13. 기관 평가 데이터 축적

- funding_applications: 기관/상품/신청·승인 금액/결과/평가 의견/보완 요청/실사 질문
- mvp_snapshots: 신청 시점 MVP 상태 고정(레벨·화면 수·기능 수·AI 수·API·사용 기간·사용자·로그·KPI·인증)
- 1차는 기록만. 통계 화면은 표본 10건+. 표시 문구 고정: "내부 프로젝트 데이터 기준 참고 경향"

## 14. 전문가 위험 분류

risk_registry: 도메인(세무/노무/법무) × 기능 패턴 × 등급(녹/황/적) + 금지 표현 + 권장 문구 + 면책문구 + 체크리스트 + 법령·기준일 + 검토자. 산출물 생성기가 자동 대조: 적색 기능에 면책·검토 요구 삽입, 금지 표현 검사, "전문가 판단 대체" 문구 차단.

## 15. 생성 결과물 (1차 5종)

| 산출물 | 방식 |
|---|---|
| A. AX 진단보고서 | 설문 요약+판정+낭비 정량 치환 |
| B. MVP 기능명세 (화면·DB 초안 포함) | 템플릿 조합+업종 조정 치환 |
| E. Claude Code 개발 프롬프트 | B 변환+금지사항·구현 순서 자동 포함 |
| G. 기관 설명자료 초안 | A+B에서 기술성·차별성·KPI 추출 |
| H. 테스트 체크리스트 | 템플릿·단계 기준 자동 생성 |

F(고객 확인서)·I(유지관리 제안)는 2차. 모든 산출물 버전 관리 + Markdown + 수동 편집. "80% 초안" 원칙.

## 18. 역할·권한

## 20. 향후 AI API 적용 지점 (2차, 수동 트리거+검토)

주관식 요약·쟁점 추출 / 모순 감지 / 추가 인터뷰 질문 생성 / 진단보고서 서술부 / 기관자료 서술부 / 프롬프트 정교화. 각 기능은 11장 양식(이유/입출력/비용/개인정보/검토자/대체 처리) 등록 후 활성화.

## 21. 1차 개발 순서 (6 스프린트)

- S1 기반: 레포·Supabase·인증·고객사/프로젝트 CRUD·대시보드 뼈대
- S2 설문 코어: 질문은행+조립기+외부 응답 화면(자동저장·조건부·진행률·모바일)+토큰 API
- S3 분석·판정: 응답 뷰어·비교·요약+판정 룰 엔진+판정 화면
- S4 Stage-Gate: 단계 관리+테스트 기록+타임라인
- S5 산출물: 템플릿 레지스트리+추천+생성기 5종
- S6 데이터·마감: 자금 기록+스냅샷+대시보드 완성+권한·QA

병행 콘텐츠 트랙(코드보다 중요): 공통 질문 60문항, 업종 모듈 3종, 패턴 라이브러리 3업종, 템플릿 8종 정의서, 위험 레지스트리 시드.

"추천 엔진을 만들지 말고, 판단 근거를 만드는 OS를 만들 것." 1차 코어 가치는 ①설문→판정→산출물 파이프라인 ②Stage-Gate 기록 ③기관 평가 데이터 축적. AI 추천·자동화는 데이터 축적 후. 진짜 자산은 코드가 아니라 질문은행·업종 패턴·템플릿 정의·위험 레지스트리 콘텐츠 — 개발 6스프린트와 콘텐츠 트랙 병행 필수.
