## PASS 1 — 마찰 감사 (실측)

간단 모드(3탭)까지 온 상태에서, 남아 있는 마찰을 화면 단위로 세었다.
기준은 "처음 보는 55세 컨설턴트가 여기서 멈추는가".

### 직접 타이핑을 요구하던 자리 13곳

| 할 일 | 무엇을 시켰나 | 판정 | 조치 |
|---|---|---|---|
| S0 회사 기본정보 7항목 | 자유 입력 | AUTO | 서류(사업자등록증·법인등기부등본) 한 장으로 채움 + **나중에 확인** |

| S14·S16 날짜·결과 | 타이핑 | KEEP | 사실 기록 |

### 그 밖에 발견한 것

1. **모르면 멈췄다.** 값 하나를 비우면 다음 화면으로 갈 수 없었다 — §59 의 P0 조건.
2. **강조 버튼이 셋이었다.** 프롬프트 생성 후 [복사] [ChatGPT 열기] [Claude 열기] 가 같은 무게였다.
3. **전문용어에 설명이 없었다.** 출원인·명세서·선행기술·TAM/SAM/SOM 이 그냥 나왔다.
4. **업무 용어가 새고 있었다.** `다음 · GO / HOLD / NO-GO`, `Judge / Devil`, `증빙 10슬롯`, `사실표 잠금`.
5. **연회색 글씨.** `text-slate-400` 이 다음 행동 안내·시간·종류에 쓰이고 있었다.
6. **준비된 정보 0/7.** 아무것도 없는 목록이 화면 위쪽 세 줄을 차지하고 아래 버튼을 밀어냈다.
7. **처음 오는 사람에게 아무 안내가 없었다.**

## PASS 2 — 상호작용 모델

### 2-1. 계층 (그대로 유지)

```
ENGINE LAYER   (무수정)  workflowDefinition · factsheetSchema · gateEngine
                         promptPackageBuilder · privacyFilter · kipoReferences
OPERATOR LAYER (확장)    currentTask · applyTask
                         + suggestions   시스템이 문장을 쓴다
                         + recommendations 시스템이 의견을 낸다
                         + koreanText    조사·어미를 정확히 붙인다
                         + glossary      용어 풀이
                         + companyDocFacts 서류에서 사실표로
UI             (재설계)  지금 할 일 카드 하나
```

### 2-2. 입력 대체 순서 (§4)

```
1. 이미 아는 값        → 묻지 않는다 (고객 기록에서 자동 시드)
2. 서류에 있는 값      → 올리면 읽는다 (사업자등록증·법인등기부등본)
3. 규칙으로 아는 값    → 시스템이 추천하고 사용자는 확인 (진행 판단·참고자료)
4. 앞에서 정한 값      → 시스템이 문장 초안을 쓰고 사용자는 확인 (핵심기술·MVP 흐름)
5. 고를 수 있는 값     → 보기로 (거래처 수·주 사용자·기존 방식)
6. 지금 몰라도 되는 값 → [잘 모르겠어요 · 나중에]
7. 그 밖에            → 직접 입력 (마지막 수단)
```

### 2-3. 나중에 확인 (§6·§7·§8)

- `project.deferred[]` 에 `{ key, label, stageKey, deferredAt }` 로 남는다. 지우는 것이 아니라 미루는 것이다.
- 기획 단계(S0~S9)에서는 미뤄 둔 것을 **다시 묻지 않는다**.
- 제출에 가까운 단계(**S7 출원 · S10 숫자 · S13 제출 전 점검 · S14 신청**)에서는 **다시 묻고**, 거기서는 [나중에] 를 주지 않는다.
- 값이 채워지면 목록에서 저절로 빠진다(`pruneDeferred`).
- 진행하기 화면에 "나중에 확인하기로 한 것 N가지" 로 늘 보인다 — 사용자가 기억할 필요가 없다.

### 2-4. 시스템이 먼저 쓴다 (§9)

```
CLICK  → 보기를 하나 고른다
WRITE  → 시스템이 회사명·업종을 붙여 문장으로 늘린다
SHOW   → "이렇게 저장됩니다" 로 저장 전에 보여 준다
CONFIRM→ 버튼 한 번
```

사실표에는 늘린 문장이, 핵심 줄기에는 고른 그대로의 짧은 이름이 들어간다.
(줄기에 문장을 넣으면 다음 초안이 그 문장을 다시 끼워 넣어 말이 겹친다.)

### 2-5. 조사·어미 (koreanText.ts)

초안 문장에서 `…확인한다을 대신하는` 같은 말이 한 번이라도 나오면 사용자는 그 시스템을 믿지 않는다.

- `hasFinalConsonant` — 한글 자모 계산으로 받침 판별. 숫자도 읽는 소리로 판별.
- `objectParticle` / `subjectParticle` / `topicParticle` — 받침에 맞는 조사. 판단 불가면 `을(를)` 로 둘 다 적는다.
- `toPhrase` — 종결어미 제거 + 이미 조립된 문장의 앞뒤(회사 소개·판정문) 제거.
- 그리고 **가능하면 조사로 잇지 않는다.** 줄표(—)와 절로 나눠 쓰면 어떤 값이 들어와도 문장이 무너지지 않는다.

### 2-6. 추천 (§5·§27)

| 자리 | 규칙 | 추천하지 않는 경우 |
|---|---|---|
| 진행 판단 | 현장문제 있음 + 고객 있음 → 진행 / 고객 없음 → 보강 후 진행 | 현장문제가 없으면 `null` |
| 참고자료 | 현장문제·핵심기술 낱말과 겹치는 사례 → 없으면 시스템 발명 기본 4종 | 근거 문장이 비면 `null` |

**진행 어려움(NO-GO)은 시스템이 만들지 않는다.** 회사를 보고 사람이 내리는 결정이다.
추천이 있으면 목록은 접혀 있고 [다르게 선택할게요] 로 편다.

### 2-7. 쉬운 한국어 (§16)

엔진의 단계 이름은 업무 용어 그대로 두고(고급 보기·문서가 쓴다), 간단 모드만 `plainStageLabel` 로 바꾼다.

| 엔진 | 간단 모드 |
|---|---|
| GO / HOLD / NO-GO | 진행 여부 판단 |
| MVP 설계 잠금 | MVP 설계 확정 |
| MVP 구현·QA | MVP 만들기 |
| 사실표 잠금 | 숫자 확인 |
| 사업계획서 7항목 | 사업계획서 쓰기 |
| 증빙 10슬롯 | 증빙 챙기기 |
| Judge / Devil | 제출 전 점검 |

단위 시험이 실제 화면 문구를 25단계까지 훑으며 금지어를 찾는다.

### 2-8. 용어 풀이 (§15·§17)

`glossary.ts` 13항목 — 출원인 · 발명자 · 선행기술 · 명세서 · 청구항 · 권리화 포인트 · 출원 중 ·
MVP · 실제 동작 기능 · TAM/SAM/SOM · 증빙자료 · 진행 판단 · 최신 서식 확인 · 확인 필요.

기본 화면은 깨끗하다. [이게 뭔가요?] 를 눌러야 1~3문장이 그 자리에서 펼쳐진다.

### 2-9. 강조 버튼 하나 (§13·§31)

프롬프트 생성 후:

```
[ 복사하고 ChatGPT 열기 ]   ← 강조 하나
복사만 하기 · Claude 에서 하기 · 내용 보기   ← 글자 링크
```

E2E 가 390 / 1024 / 1440 / 1920 에서 `button.bg-brand-600` 이 정확히 1개인지 확인한다.

### 2-10. 목표 (§48·§49)

| 항목 | 목표 | 실측 |
|---|---|---|
| 새 프로젝트 → 첫 프롬프트 클릭 | 5~7 | **7** |
| 다음 프롬프트 | 1~3 | **1** |
| 첫 프롬프트까지 타이핑 없이 처리 | ≥80% | **100%** (6단계 중 0개) |
