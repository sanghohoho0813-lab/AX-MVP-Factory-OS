# 화면 규칙 (Design System)

새 화면을 만들거나 고칠 때 이 문서의 규칙을 따른다.
목적은 "예쁘게"가 아니라 **매일 켜도 피곤하지 않게** 하는 것이다.

부품은 `src/components/ui/primitives.tsx`, 글자 크기는 `src/index.css` 에 있다.

---

## 1. 한 화면은 세 단계로만 말한다

| 단계 | 무엇 | 어떻게 |
|---|---|---|
| 1 | 지금 봐야 하는 것 | 화면 맨 위, `t-page` / `t-card`, 필요하면 왼쪽 강조선 |
| 2 | 현재 상태 | 요약 숫자·목록, `t-card` / `t-sub` |
| 3 | 상세·참고 | `Disclosure` 로 접어 둔다 |

3단계를 펼친 채로 두지 않는다. 처음 보이는 것이 적을수록 좋다.

## 2. 색

| 색 | 뜻 | 예 |
|---|---|---|
| 빨강 `danger` | 마감 지남 · 서류가 없어 막힘 · 되돌릴 수 없는 행동 | "2일 지남", "서류 3건" |
| 주황 `warning` | 임박 · 고객 회신 대기 | "내일까지", "고객 대기" |
| 초록 `success` | 완료 · 확인됨 | "완료" |
| 브랜드 `brand` | 선택됨 · 주요 행동 · 새로 온 것 | 기본 버튼, 선택된 탭 |
| 무채색 | 그 밖의 전부 | |

- **업무 종류·기록 종류·일정 종류는 색으로 구분하지 않는다.** 지름 8px 점(`Dot`)만 쓴다.
- 값이 0이면 색을 쓰지 않는다. 아무 일도 없는데 화면이 빨개지면 안 된다.
- 급한 카드도 배경을 칠하지 않는다. 왼쪽 3px 선(`Surface showEdge`)으로만 표시한다.
  **숫자 칸(`MetricTile`)·목록 카드·'지금 이것부터' 줄에도 똑같이 적용된다.** 옅은 바탕이라도
  네 칸 중 세 칸이 물들면 어느 것이 제일 급한지 오히려 안 보인다 — 급한 순서는 정렬이 이미 말한다.
- 색만으로 상태를 전하지 않는다. 항상 글자 라벨을 함께 둔다.

## 3. 글자

`src/index.css` 의 여섯 단계만 쓴다. `text-[0.85rem]` 같은 임의 크기를 새로 만들지 않는다.

| 클래스 | 크기 | 쓰는 곳 |
|---|---|---|
| `t-page` | 25.6 / 28.8px | 화면 제목 (한 화면에 하나) |
| `t-section` | 19.2px | 구역 제목 |
| `t-card` | 16.8px | 카드에서 먼저 읽히는 줄 |
| `t-body` | 16px | 본문 |
| `t-sub` | 14.4px | 보조 설명 |
| `t-meta` | 13.1px | 배지·메타데이터 **전용** |
| `t-num` | 21.6 / 24.8px | 큰 숫자 |

- 굵게(`font-bold`)는 제목에만. 설명은 `font-medium` 이하.
- 글자 색은 세 단계 — `text-slate-900` 본문, `text-slate-600` 보조, `text-slate-400` 메타.

## 4. 여백과 크기

- 모바일 좌우 여백 16px, 카드 안 16~20px, 구역 사이 24px, 카드 사이 10~16px.
- 누르는 자리는 44px 이상 (`tap` 클래스 또는 `min-h-11`).
- 카드 안에 카드를 넣지 않는다. 목록은 `ListSurface` + `ListRow` (구분선만).

## 5. 버튼

- 한 카드·한 구역에 **강조 버튼(primary)은 하나**.
- `primary` 주요 행동 / `secondary` 보통 / `ghost` 부수 / `danger` 지우기·되돌릴 수 없는 것.
- 모바일에서 버튼이 셋을 넘으면 `BottomSheet` 로 옮긴다.

## 6. 배지

- 한 카드에 배지는 **두 개까지**.
- 항목이 여섯 개를 넘는 조각 묶음은 접는다. 기준은 **한 문장으로 말할 수 있어야 한다**:
  *손이 갈 일이 남았으면 보이고, 끝났거나 아직 시작 안 했으면 접힌다.*
  - 보인다 — 마감 지남 · 마감 임박 · 진행 중 · 고객 대기 · **보류**(사람이 멈춰 둔 것이라 이유를 봐야 한다)
  - 접힌다 — 완료 · 시작 전 · 해당 없음
- **접힘 단추는 무엇이 접혔는지 말한다.** `그 외 6` 이 아니라 `완료 3 · 시작 전 2`.
  개수만 쓰면 기준을 사용자가 추측해야 하고, 추측하게 만드는 순간 접기는 실패한다.
- 조각을 건드리면 그 카드는 펴 둔다 — 방금 누른 것이 접힘 속으로 사라지면 무엇이 바뀐 건지 알 수 없다.
- **값이 0이면 조각을 그리지 않는다.** '미수금 없음' · '서류 0/10' 은 아무 일도 없다는 뜻인데
  카드마다 두 칸을 차지한다.
- 종류·분류는 배지 대신 무채색 글자.
- 배지 색은 위 색 규칙을 따른다.

## 7. 모바일

- 하단 내비게이션 5칸(오늘·고객·이벤트·일정·더보기)은 고정이다. 늘리지 않는다.
- 상단은 `[메뉴] [화면 이름] [알림]` 세 개까지.
- 입력이 여러 칸이면 화면을 밀어내지 말고 `BottomSheet` 로 띄운다.
- 본문 맨 아래에는 `pb-safe-nav` 로 하단 내비 높이만큼 여백을 둔다.

## 8. 움직임

- 등장 620ms, 창 380ms, 색 전환 220ms. 반복 애니메이션은 쓰지 않는다.
- `ax-rise` 등장 / `ax-stagger` 차례로 / `ax-pop` 창 / `ax-lift` 손 올렸을 때.
- '화면 움직임 줄이기' 설정과 OS `prefers-reduced-motion` 에서 전부 멈춘다.

## 8-1. 색은 두 갈래로만 (D-25)

| 갈래 | 어디에 | 무엇을 말하나 |
|---|---|---|
| 어디인가 | 왼쪽 메뉴 아이콘 · 묶음 머리 칩(20~28px) | 지금 보는 곳이 어디인지 |
| 얼마나 급한가 | 카드 왼쪽 · 숫자칸 위쪽 3px 선, 숫자 글자색 | 마감 지남=빨강 · 7일 이내=주황 · 그 밖=무채색 |

- 업무 종류(특허·벤처인증 …)는 색으로 칠하지 않는다. 점 하나만.
- 급한 정도의 기준은 **경고 건수가 아니라 다음 할 일의 마감과 수금 연체**다.
  건수로 매기면 거의 모든 업체가 빨강이 되어 목록이 통째로 물든다.
- 목록의 정렬 순서와 색이 같은 방향을 보아야 한다 — 위에서부터 색이 옅어질 것.
- **바탕은 칠하지 않는다(D-57).** 옅게라도 칠하면 다섯 장 중 네 장이 물들어 제일 급한 하나가 사라진다.
  실측에서 큰 면에 칠해진 바탕이 19개였고, 걷어낸 뒤 4개(전부 '받을 돈 연체')만 남았다.

**세 번째 갈래 — '얼마나 오래됐나' (D-65 · D-66).** 옅은 브랜드색 pill 두 자리만 쓴다.

| 어디에 | 무엇 |
|---|---|
| 목록 카드 | `25년차` — 업력. 정책자금·벤처인증 자격이 여기서 갈린다 |
| 목록 카드 · 계약 카드 | `계약 1년 6개월째` — 계약한 지 얼마나 됐나 |

둘 다 "이 숫자로 판단이 갈린다" 는 같은 뜻이고, 둘 다 옅은 바탕 pill 하나다.
**여기서 더 열지 않는다.** 세 번째 pill 을 넣고 싶으면 그때 무엇을 뺄지 함께 정한다 —
D-57 에서 칠해진 면 19개를 4개로 줄인 작업이 그대로 되돌아온다.

**클래스 이름을 이어 붙이지 말 것.** `` `text-nav-${accent}` `` 는 CSS 가 아예 생성되지 않는다(D-26).
이름을 통째로 적은 `Record` 에서 꺼낸다. 확인: `grep -o "\.text-nav-[a-z]*" dist/assets/*.css`

## 9. 한 줄 안에 글자와 버튼을 같이 두지 않는다 (짜부라짐 금지)

이것 하나로 "글자가 세로로 한 자씩 흐르는" 현상이 거의 다 생겼다.

```jsx
/* 하지 말 것 — 360px 에서 글자 칸이 20px 로 눌린다 */
<div className="flex flex-wrap items-center gap-3">
  <p className="min-w-0 flex-1">긴 안내 문구…</p>
  <div className="shrink-0"><Button>클라우드로 옮기기</Button></div>
</div>
```

`flex-1` 은 기준폭이 `0` 이라 브라우저가 "이미 다 들어갔다" 고 판단한다. 그래서
`flex-wrap` 이 있어도 줄이 넘어가지 않고, 글자 칸만 계속 좁아진다. 옆의 `shrink-0`
버튼은 한 뼘도 양보하지 않으므로 결국 글자가 세로로 흐른다.

```jsx
/* 이렇게 — 휴대폰에서는 줄을 나누고, 넓어지면 한 줄로 합친다 */
<div>
  <p className="break-keep">긴 안내 문구…</p>
  <div className="mt-3 flex flex-wrap gap-2"><Button>클라우드로 옮기기</Button></div>
</div>
```

규칙
- 한 줄짜리 flex 안에 **글자 + 고정폭 컨트롤(select · date · 버튼)** 을 같이 두려면
  좁은 폭에서 줄을 나눈다: 글자 쪽에 `w-full sm:w-auto sm:flex-1`.
- 데스크톱 한 줄 배치를 지키고 싶으면 감싼 칸에 `sm:contents` 를 주고 자식에 `order-*`
  를 달아 원래 순서를 되돌린다 (수금 줄이 이 방식이다).
- `<select>` 의 폭은 가장 긴 선택지가 정한다. 좁은 곳에 넣기 전에 그 폭을 생각한다.
- 화면 이름이 위쪽 띠와 같으면 큰 제목을 휴대폰에서 숨긴다(`ScreenTitle`·`PageHeader`
  가 자동으로 판단한다). 같은 말을 두 번 하지 않는다.

## 11. 간단 모드 (컨설팅 작업실)

`/studio/:id` 는 기본이 **간단 모드**다. 화면은 `CurrentTask` 하나만 그리고 단계·프롬프트 종류를 모른다.

- 강조 버튼(`variant="primary"`)은 **화면당 하나**. 위에 강조 블록이 이미 있으면 카드는 `quiet` 로 낮춘다.
- 간단 모드 본문은 `max-w-3xl`. 고급 보기(`?adv=1`)만 전폭을 쓴다(표·2단이 있으므로).
- 단계별 색을 만들지 않는다. brand + 무채색, 급할 때만 danger/warning/success.
- 개발자 낱말을 화면에 쓰지 않는다: `draft`·`superseded`·`GO/HOLD`·`Judge/Devil`·`Block`·`Skip`·`S0~S16`·`슬롯`·`잠금`.
  단위 시험이 실제 화면 문구를 25단계까지 훑으며 금지어를 찾고, E2E 가 간단 모드 화면을 확인한다.
  단계 이름은 `plainStageLabel` 로 한 번 걸러 쓴다 — 엔진 이름은 그대로 둔다.

## 11-2. 빈 칸을 늘어놓지 않는다

값이 없는 항목을 목록으로 펴 두면, 정작 적혀 있는 값이 그 사이에 묻힌다.

- 기본은 **적힌 것만** 보여 주고, 빈 칸은 아래 한 줄(`아직 안 적은 N칸 채우기`)로 접는다.
- 아무것도 안 적혀 있으면 접을 것이 없으므로 그때는 전부 편다.
- 접었다고 지운 것이 아니다 — 한 번 누르면 그대로 다 나온다.

## 11-2b. 목록 카드의 회사 정보는 두 무게로 나눈다

한 줄에 회색으로 다 붙이면 (`444-87-04089 · 1년차 · 최정철 · 경기 남양주시`) 아무것도 안 읽힌다.

- **색**(`bg-brand-50 text-brand-700` pill) — **N년차 하나뿐이다.** 정책자금·벤처인증 자격이 업력에서
  갈리므로 목록에서 가장 먼저 찾는 숫자다. 색을 쓰는 자리를 여기로 제한한다 — 늘리면 다시 알록달록해진다.
- **진하게**(`slate-800 font-semibold`) — 대표자 · 계약 단계. 전화를 걸거나 상태를 볼 때 쓰는 값.
- **흐리게**(`slate-500`) — 지역 · 업종. 어느 회사인지 떠올리는 배경.
- **자체 줄 + `tabular-nums`** — 사업자등록번호. 읽는 값이 아니라 서류에 옮겨 적는 값이라,
  카드마다 같은 자리·같은 자릿수에 있어야 여러 장을 훑을 때 눈이 바로 찾는다.
- 메타 줄은 `t-meta`(13px)가 아니라 `t-sub`(14.4px). `t-meta` 는 배지 전용이다.
- **날것을 찍지 않는다.** 업력을 못 읽으면 설립일 원본(`20020216`)을 대신 보여 주지 말고 비운다.
  사업자번호는 `formatBusinessNumber` 를 거친다.

## 11-2c. 서식이 정해진 번호

사업자등록번호 · 법인등록번호 · 전화번호는 **기록에 어떤 모양으로 들어와 있든** 화면에는
서류에 적히는 모양으로 보여 준다. `formatNumberOf(kind, value)` 를 거친다.

- `3138112508` → `313-81-12508` · `01023456789` → `010-2345-6789` · `1101111234567` → `110111-1234567`
- **자릿수가 안 맞으면 원문 그대로 둔다.** 모자란 번호를 그럴듯하게 지어내지 않는다.
- 번호는 `tabular-nums` 로. 카드마다 자릿수가 흔들리면 훑을 수 없다.

**복사는 세 가지를 준다.** 쓰는 곳마다 필요한 모양이 다르기 때문이다.

| 누르는 곳 | 복사되는 것 | 언제 쓰나 |
|---|---|---|
| 조각 하나 (`313`) | `313` | 신청서 칸이 `[ ]-[ ]-[ ]` 로 나뉘어 있을 때 |
| 옆의 복사 아이콘 | `313-81-12508` | 서류·메일·카톡에 그대로 적을 때 |
| `[숫자만]` | `3138112508` | 홈택스처럼 하이픈을 안 받는 입력칸 |

프로필 머리의 `전체 복사` / `숫자만` 은 카드 전체를 같은 두 모양으로 복사한다.

**조각 복사가 기본값이 아니라 추가값인 이유.** 칸이 나뉜 신청서에서는 전체를 붙이고 손으로
하이픈을 지우는 것이 아니라 조각을 하나씩 옮겨 붙이는 것이 맞다. 주민등록번호를 앞자리·뒷자리
따로 넣는 것과 같은 일이고, 법인등록번호(`110111-1234567`)가 정확히 그 모양이다.

- 나누는 기준은 **보이는 값의 하이픈**이다(`numberSegments`). 조각이 전부 숫자일 때만 나눈다 —
  자릿수가 안 맞아 원문 그대로 둔 값은 나누지 않는다.
- 조각은 하이픈을 사이에 두고 붙여 그린다. 한 번호로 읽혀야지 세 개의 칩으로 보이면 안 된다.
- **조각 줄은 절대 접지 않는다** (`flex-nowrap whitespace-nowrap`). 접히면 번호가 세로 기둥이 된다(D-23).
  대신 값 칸에 `min-w-[9.5rem]` 을 주어, 폭이 모자라면 **값 전체가 라벨 아래 줄로** 내려간다.
  실제로 360px + 큰 글자에서 `123-45-67890` 이 5줄로 쌓인 것을 `qa:squeeze` 가 잡았다.
- 복사된 조각은 1.5초 동안 옅은 초록 바탕이 된다 — 어느 조각까지 붙였는지 놓치지 않게.

E2E 가 실제 클립보드를 읽어 세 경로를 모두 확인한다(3조각·2조각·전체·숫자만).

## 11-1-2. 오늘 화면은 네 구역뿐이다 (D-70)

매일 여는 화면이다. 구역이 여덟이면 매일 스크롤하게 되고, 제일 많이 쓰는 '할 일 적기' 가 묻힌다.

| 남긴 것 | 왜 |
|---|---|
| 오늘 할 일 | 하루를 실제로 굴리는 것. 맨 위, 브랜드색 테두리 |
| 지금 이것부터 (3건) | 규칙이 찾아 준 급한 것 |
| 무슨 일이 있었나요 | 통화·결정을 그 자리에서 남긴다 |
| 고객 이벤트 | 고객 플랫폼에서 오는 것 |

없앤 것 — 컨설팅 다음 행동 · 챙겨야 할 업체 · 돈 · 지원사업 마감. 가리키던 화면은 그대로 있고,
숫자 네 칸(이번 주 마감 · 고객 회신 대기 · 받아야 할 돈 · 새 고객 이벤트)이 한 줄로 남아 그리로 간다.

- **제목을 두 번 쓰지 않는다.** h1 이 '오늘 할 일 N건' 이면 카드 안에 또 쓰지 않는다.
- 할 일은 **눌러서 고친다** — 내용과 기한을 함께. 고칠 수 없으면 지우고 다시 적게 되고,
  그러면 언제 적었는지가 사라진다.

## 11-2b-2. 목록 정렬 — 기준은 고르고, 순서는 번호로 보인다 (D-72)

`급한 순`(기본) · `가나다순` · `업력순` · `계약 오래된 순`. 고른 기준은 브라우저에 기억한다.

- 값이 없는 업체(설립일·계약일 미기재)는 **언제나 맨 뒤**. 안 그러면 목록을 못 믿는다.
- 카드마다 옅은 회색 번호. 정렬을 바꿨을 때 순서가 바뀐 것이 눈에 보이게 — 읽는 값이 아니라 눈금이다.
- **업체명 상자에 색을 넣지 않는다.** §8-1 이 색을 이미 세 갈래로 쓰고 있어서,
  여기에 더하면 D-57 에서 걷어낸 알록달록한 목록이 그대로 돌아온다.

## 11-2c-2. 칸은 대표가 만들고 대표가 없앤다

회사 기본 정보의 네 묶음(회사·사람·연락처·인증서)마다 `[+ … 에 칸 추가]` 가 있다.
업종마다 챙길 값이 다르므로, 개발을 기다리는 대신 그 자리에서 칸을 만든다.

**지우기는 두 가지이고 낱말이 다르다.** 같은 '지우기' 로 쓰면 무엇이 사라지는지 알 수 없다.

| 칸 | 단추 | 결과 |
|---|---|---|
| 표준 칸 | `값 지우기` | 값만 비운다. 칸은 남아 '아직 안 적은 칸' 이 된다 |
| 직접 만든 칸 | `칸 없애기` | 칸째 없앤다. 되돌릴 수 없어 한 번 더 묻는다 |

- 직접 만든 칸은 **이름도 함께 고친다** — 오타 때문에 지웠다 다시 만들지 않게.
- 직접 만든 칸은 각 묶음 **끝**에 붙인다. 표준 칸 사이에 끼우면 업체마다 순서가 달라진다.
- **칸을 만들 수 있을 때는 빈 묶음의 머리를 남긴다.** 안 그러면 아무것도 안 적은 묶음이
  접힘에 묻혀 그 묶음에 칸을 만들 길이 없어진다.
- 고칠 때 `[저장]` `[취소]` 를 눈에 보이게 둔다. 포커스가 빠지면 저장되는 방식은 쓰지 않는다 —
  `값 지우기` 를 누르는 순간 저장이 먼저 일어나 서로 싸운다.
- 비밀번호·주민등록번호는 **직접 만든 칸에도** 적지 않는다. 만드는 자리에 그렇게 적어 둔다.

## 11-2d-2. 돈 — 청구액과 '진짜 내 돈' 을 나눈다 (D-73)

성공보수 2,000만원을 받아도 일부는 영업자에게 나간다. 청구액만 보여 주면 실제로 남는 돈을
매번 다시 계산하게 된다.

- 수금 항목마다 `영업자 수수료` 칸. **저장하는 것은 청구액과 수수료 둘뿐이다.**
- `내 몫`(= 청구액 − 수수료)과 `이익률`은 **저장하지 않고 매번 계산한다**.
  저장하면 금액을 고쳤을 때 옛 이익률이 남는다 — 돈 화면에서 그건 거짓말이 된다.
- 머리 네 칸: `청구 합계` · `영업자 수수료` · `내가 받는 돈` · `못 받은 내 돈`.
- 적는 동안 이익률이 따라 움직인다(계산기처럼).
- 청구액이 미정이면 이익률 줄이 **비어 있다**. 수수료가 더 크면 **음수를 그대로** 보여 준다.

## 11-2d-3. 돈은 어디서나 '내 몫' 이다 — 청구 기준은 작은 글씨 (D-74 · D-75)

같은 업체의 미수금이 화면마다 다르면 대표는 어느 것이 진짜인지 또 계산한다.

- 돈을 더하는 자리는 전부 `netAmountOf` 하나를 쓴다. 이름도 하나다 —
  `못 받은 내 돈`(목록·운영·개요) · `받아야 할 내 돈`(오늘) · `받은 내 돈`(진행 요약).
- 내 몫 ≠ 청구액일 때만 힌트에 `청구 기준 900만원` 을 붙인다. 연체 건수와 같이 나오면
  `예정일 지난 건 3건 · 청구 기준 900만원` — **둘 다** 적는다. 카드 조각은 `title` 로만 보여 준다(조각이 길어지면 줄이 는다).
- 수수료가 있는 항목에만 `영업자 이름` 칸이 열린다. 항목 줄은 `최영업 몫 빼고 → 내 몫 4,000,000원`,
  위 칸 힌트는 사람별 합계 `최영업 1,500,000원 · 박영업 500,000원`.
- 항목 줄은 데스크톱에서도 **줄바꿈을 허용**한다(`sm:flex-wrap`). 수수료 줄이 같은 줄에 끼면 이름 칸이 0px 로 눌린다.

## 11-2b-3. 검색은 '내가 적어 둔 것 전부' 에서 (D-76)

- 대상: 기본 정보 전부 + 직접 만든 칸의 이름·값 + 영업자 이름 + 보험사·상품명. 업무 일기는 제외.
- 숫자·하이픈만 넣으면 하이픈을 걷어낸 번호에서도 찾는다 — `6789` 로 전화 뒷자리, `110111` 로 법인번호.
- 자리 표시 문구가 범위를 말한다: `업체명·담당자·번호·직접 만든 칸으로 찾기`.

## 11-1-3. 할 일 고치기에는 업체 칸도 있다 (D-77)

- 고치기 시트: 할 일 · 언제까지 · **업체**. 업체 목록은 보관·종료를 뺀 것이되, 지금 붙은 업체는 목록에 없어도 맨 위에 남긴다.
- 상세 머리말 둘째 줄에 `현금 + 보험 · 1년 7개월째`. 누르면 개요 탭.

## 11-2d-4. 영업자 정산 — 고객 입금 → 영업자 지급, 순서는 하나 (D-78 · D-81)

- 위 네 칸: `지금 줄 돈`(warning) · `고객 입금 전` · `이미 준 돈` · `수수료 전체`. 첫 칸만 색을 쓴다.
- 사람별 패널: 머리에 이름과 `지금 줄 돈`, 아래에 항목 줄(체크 · 업체 → · 항목 · 금액 · 상태 조각).
  상태 조각은 셋뿐 — `줄 돈 · 고객 입금 날짜`(warning) · `고객 입금 전`(흐림) · `지급 날짜`(success).
- 고객 입금 전 항목의 체크는 **잠긴다**(disabled + 흐림). 수금 탭도 같다.
- 입금 조각과 지급 조각은 **날짜 칸**이다 — 체크한 날이 아니라 들어온 날·준 날을 적는다.

## 11-2b-4. 보기와 정렬은 나란히, 하는 일이 다르다 (D-79 · D-80)

- `보기` 가 먼저, `정렬` 이 다음. 보기는 무엇을 보일지, 정렬은 그 순서다. 둘 다 기억한다.
- 보기가 '전체' 가 아니면 칸 테두리·글자를 브랜드색으로 — 걸러진 상태임을 잊지 않게.
- 카드 흐린 줄 첫 자리에 계약 종류. 검색이 회사명 아닌 칸에 맞았으면 이름 줄 바로 아래
  `찾은 곳 · 칸 이름 값` 한 줄(브랜드색). 회사명이 맞았으면 없다.

## 11-2e. 서류함 — 기본 10종과 직접 만든 칸을 한 줄로 (D-82 · D-83)

- 직접 만든 칸은 기본 서류와 **같은 카드**를 쓴다. 다른 것은 옅은 브랜드색 `직접 만든 칸` 조각과
  카드 맨 아래 `이름 고치기` · `칸 없애기` 두 줄뿐이다.
- 만드는 줄은 점선 테두리 한 칸: `서류 이름` + `유효기간(개월)` + `서류 칸 추가`.
  휴대폰에서는 이름 칸이 한 줄을 다 쓴다(`w-full sm:w-auto sm:flex-1`) — 세 개를 한 줄에 두면 §9 가 그대로 재현된다.
- 올린 파일 줄은 `파일 교체` · `내려받기` · 파일명 순. 파일이 없으면 `내려받기` 를 그리지 않는다.
- 로컬 모드에서는 두 단추가 잠기고 `title` 로 이유를 말한다 — 안 보이게 감추지 않는다.

## 11-2f. 한꺼번에 올리기 — 세 단계 배지, 근거는 사람 말로 (D-84)

- 판별 결과는 `확실`(success) · `확인 필요`(warning) · `모름`(무채색) 셋뿐. 점수·확률을 보여 주지 않는다.
- 근거 한 줄은 서류의 실제 문구를 따옴표로 — "제목 '사업자등록증', '개업연월일'". 왜 그렇게 가렸는지 대표가 검증할 수 있어야 한다.
- 줄마다 `어느 칸에` 고르는 칸 · `발급일` · `이것만 올리기`. 안 고른 줄은 고르는 칸 테두리가 warning 이다.
- 아래 단추 둘: `확실한 것만 올리기`(secondary) · `고른 것 전부 올리기`(primary). 강조는 하나.
- 목록 카드 꼬리에 `서류 올리기` 를 `업체 열기` 앞에 둔다 — 회색, 올리면 브랜드색.

## 11-2d. 계약과 이력 — 한 줄은 요약, 자세한 것은 눌러야 나온다

업체를 여는 이유의 절반은 "이 회사 언제 계약했지, 얼마짜리였지, 우리가 뭘 해 줬더라" 다.
그 답은 개요에서 **접지 않는다**. 대신 한 줄로 줄이고, 건별 숫자는 눌러야 나오게 한다.

**계약 카드** — 한 줄에 넷만 둔다.

- 계약일 (`2025-03-15`, `tabular-nums`)
- 몇 달째인가 (`1년 6개월째 (18개월)`) — 옅은 브랜드색 pill. §8-1 이 연 두 번째 자리다.
- 방식 (`현금` · `보험` · `현금 + 보험`) — 테두리만 있는 회색 pill
- 돈 한 줄 (`현금 3,000,000원 · 월납 750,000원`)

보험 건별(보험사·상품명·월납보험료·가입일·납입기간)은 `[보험 2건 자세히]` 뒤에 둔다.
세 건이 펼쳐져 있으면 계약일이 어디 있는지 다시 찾게 된다.

- **몇 달째인가는 저장하지 않는다.** 매번 계산한다 — 저장하면 내일도 18개월째다.
- **금액은 반올림하지 않는다.** 요약 줄도 `formatKrw`. `formatKrwCompact` 는 만원 단위로
  반올림하므로 계약 금액에 쓰면 없는 숫자를 만든다.
- **주민등록번호·증권번호 칸을 만들지 않는다.** 칸이 있으면 적게 된다.
- 목록 카드에는 괄호 없이 짧게 (`계약 1년 6개월째`). 계약 전이면 계약 단계를 대신 보여 준다.

**해 드린 일 카드** — 새로 적게 하지 않는다. 이미 저장된 `status: 'done'` 과 `completedAt` 을
모아 최근 순으로 보여 줄 뿐이다. 줄을 누르면 그 업무 카드로 간다.

**진행 중인 업무는 여기 넣지 않는다.** 같은 화면 맨 위 '지금 할 일' 카드에 이미 있다.
실제로 처음 만들 때 넣었다가 스크린샷에서 `특허 출원` 이 한 화면에 두 번 찍힌 것을 보고 뺐다.

## 11-3. 범례가 필요하면 화면이 진 것이다

'빨강 = 마감 지남' 같은 색 설명을 화면에 적어 두지 않는다. 조각에 `7일 지남` 이라고
글자로 쓰여 있으면 색이 무슨 뜻인지 물어볼 일이 없다.

## 12. 마찰 제거 규칙 (처음 쓰는 50대 기준)

- **묻기 전에 순서를 지킨다**: 아는 값 → 서류에서 읽기 → 규칙 추천 → 문장 초안 → 보기 → [나중에] → 직접 입력.
- **모르면 넘어갈 수 있다**: 기획 단계의 질문에는 `deferrable` 을 붙인다. 제출에 가까운 단계(S7·S10·S13·S14)에는 붙이지 않는다.
- **시스템이 만든 문장에는 `koreanText` 를 쓴다**: 조사를 직접 이어 붙이지 말고, 가능하면 줄표(—)와 절로 나눈다.
- **전문용어에는 `glossary` 열쇠를 붙인다**: 화면에 설명을 늘어놓지 말고 [이게 뭔가요?] 로 접어 둔다.
- **`text-slate-400` 은 장식 아이콘에만**: 읽어야 하는 글자는 `slate-500` 이상. `t-meta`(13px)는 배지 전용.
- **준비된 정보가 0이면 그 목록을 감춘다**: 빈 목록은 화면만 밀어낸다.
