# 원본 OS 전부 옮기기 — 전체 지도와 순서 (D-91)

2026-09-23 · 대표 지시: "기존에 만들어 놓은 것들에서 **일부 기능만** 끌고 왔더라. **전부** 가져왔으면 좋겠다.
로그인 같은 것만 빼고 — 순수하게 눌렀을 때 어떻게 기능하고 어떤 결과가 나오는지. 왼쪽 목차도 똑같아야 한다.
그리고 이 OS 를 동료 컨설턴트에게 월 구독으로 팔 거다. 모듈은 내가 승인해 줘야만 열리는 구조로 간다."

## 0. 한 줄 요약

지금까지 옮긴 것은 **규칙 계산(엔진)** 이다. 원본의 **화면·업무 흐름·기록 관리**는 대부분 안 옮겼다.
원본 4벌의 화면을 합치면 **메뉴 47개 · 약 2만 줄**이다. 이것을 모듈 단위로 순서대로 옮긴다.

## 2. 무엇을 안 옮기는가 (대표 지시대로)

- 로그인·가입·초대코드·비밀번호 재설정 — 이 OS 는 이미 자체 인증이 있다.
- 결제·구독 PG(토스·Stripe) — 승인 상태만 관리하고 결제는 붙이지 않는다.
- PIN 화면 잠금 — 이 OS 에 이미 있고, 모듈마다 또 걸 이유가 없다.
- 외부 체험 게이트(`miraeailab.com/tool-gate.js`) — 우리 안에서 승인으로 대체한다.
- 원본에서도 안 쓰는 죽은 코드: 정책자금 `cases.ts`(238줄) · `DiagnosisForm.tsx`(502줄).
- 신고관리시스템 **비밀번호 저장 칸** — CLAUDE.md 금지 사항(평문 저장). 대신 "어디에 보관했는지" 메모만.

## 3. 목차(햄버거)를 어떻게 나누는가 — 결정

**OS 목차는 그대로 두고, 모듈 안에 2단 목차를 둔다.**

- 넓은 화면: 도구 화면 왼쪽에 모듈 목차가 한 칸 더 선다 (OS 사이드바 → 모듈 목차 → 내용).
- 휴대폰: 상단에 **모듈 햄버거**가 하나 더 생긴다. OS 햄버거는 그대로 왼쪽에 있다.
- 주소가 화면마다 갈린다: `/tools/employment/dashboard`, `/tools/employment/companies` …
- 모듈 목차는 `toolRegistry` 의 `sections[]` 하나로 정의한다 — 새 화면을 더하면 목차·주소·잠금이 따라온다.

**왜 OS 목차를 갈아끼우지 않는가**: (1) 모듈 안에서도 '오늘·고객 운영' 으로 한 번에 나가야 한다.
(2) 모듈을 따로 파는 구조에서 "이 모듈에 무엇이 들어 있는지" 가 목차로 보여야 판다.
(3) 목차가 통째로 바뀌면 대표가 지금 어디에 있는지 잃는다.

## 4. 모듈 잠금(구독) 구조 — 결정

- 모듈마다 상태 세 가지: **잠김 · 체험(기간) · 열림**. 대표(소유자)만 바꾼다.
- 잠긴 모듈도 **목차와 첫 화면은 보인다.** 눌러서 쓰려 하면 "대표 승인이 필요합니다" 가 뜬다 — 팔려면 보여야 한다.
- 기본(오늘·일정·고객 운영·서류함·업무 일기)은 늘 열린다. 잠금은 모듈에만.
- 결제는 붙이지 않는다. 상태만 관리하고, 나중에 결제를 붙일 자리만 비워 둔다.
- 저장: 로컬 모드는 브라우저, 클라우드 모드는 추가 전용 표 하나(`module_access`). SQL 은 써 두되 **대표가 실행**한다.

## 6. 업체·고객 데이터를 어떻게 합치는가 (중요)

원본들은 저마다 고객 명단을 따로 들고 있었다. 그대로 옮기면 **명단이 네 벌**이 된다.

- **업체(회사)는 이 OS 의 고객 운영 하나로 통일한다.** 모듈은 업체를 만들지 않고 고른다.
- 모듈만 쓰는 것(직원·연구과제·연구노트·리드·교육 기록 …)은 **모듈 데이터**로 따로 둔다.
- 모듈 데이터는 업체 id 를 물고 있는다 — 업체를 열면 모듈이 무엇을 쌓았는지 보인다.
- 원본의 고객 CSV 가져오기는 **고객 운영의 가져오기로 합친다**.

## 7. 지키는 것

- 규칙 계산은 원본 그대로. 화면만 이 OS 것으로.
- LLM 호출 0. 원본의 'GPT 프롬프트' 기능은 **프롬프트 글을 만들어 복사**하는 것이 전부였다 — 그대로 옮긴다.
- 주민등록번호·비밀번호는 저장하지 않는다. 명부 파일은 브라우저 안에서만 읽는다.
- DB 는 추가만. 모듈 데이터는 payload/추가 표로.

### 6단계 · 모듈 잠금

- 모듈마다 **잠김 · 체험(14일) · 열림**. 도구함 화면에서 대표가 바꾼다.

- 결제는 붙이지 않았다 — 화면에 그렇게 적혀 있다.

### 덧붙여 마저 옮긴 것

- 크레탑 **핵심지표 검수**(어느 줄에서 나온 숫자인지) · **숫자 추출기**(줄 단위 검수 + CSV)
- 창업감면 **판정 결과서**(판정 화면에서 적은 것으로 바로, 복사·인쇄)

이로써 **목차의 모든 칸이 진짜 화면**이다. '아직 옮기지 않았습니다' 자리 표시(ModulePending)는 지웠다.

| 영업 도구 | 제안 주제 목록만 | 영업 카드(방문 리포트·제안서·견적/업무범위서·계약 준비팩 등 17칸) · 성과 분석 · 상품 관리 |
| 고용지원금 | 업체별 대상자·회차 | 업체 탭(개요·업체 서류·수수료 정산·업무 일지·기관 보고서) · 엑셀 가져오기 마법사 · 대시보드 칸 |
| 연구소 | D-91 에서 새로 짠 화면 | **원본 화면 16개를 그대로**(`labcare/orig/`) — 도면 편집기(FloorPlanner) 포함 |

| 창업감면 | D-88 에서 새로 짠 화면 | **원본 화면 그대로**(`startupTax/orig/`) — 연·월·일 고르기 · 결과 카드 15종 · A4 결과서 |

### 원본을 '그대로' 옮긴 방법

- 원본 화면 파일을 복사하고, 불러오는 경로만 바꿨다. 글자·배치·색은 손대지 않았다.
- 원본이 Next.js 였던 곳(연구소·정책자금)은 `next.tsx`(Link) · `nav.ts`(useRouter 등)가 원본 주소를
  모듈 주소로 바꿔 준다(`/clients/{id}` → `/tools/labcare/clients?cid={id}`).
- 원본은 사이드바 하나였지만 이 OS 는 사이드바 + 모듈 목차 두 개라 본문이 좁다. 그래서 원본의 화면 폭 기준
  (`lg:` · `xl:`)을 **본문 폭 기준**(container query)으로 바꿨다 — 원본과 같은 칸 배치가 나온다.
- 원본 글자 크기도 맞췄다: 연구소는 원본 글자 단계(본문 19px)를 연구소 화면 안에서만, 창업감면은
  원본의 1.25배를 넓은 화면에서만 쓴다(휴대폰 폭에서 키우면 칸이 좁아져 글자가 잘려서).
- 원본 색 이름(`status-*` · `navy-50/100` · `brand`)을 테마에 더했다. 빠져 있으면 빨간 단추가 투명하게 보였다.

### 업체는 여전히 고객 운영 하나뿐

- 연구소 고객사 추가 → **고객 운영 업체를 고른다.** 회사명·대표자·주소는 고객 운영 기록을 비춘다.
- 정책자금 '고객으로 저장하기' → **저장할 고객 운영 업체를 고른다**(업체에서 열었으면 골라져 있다).
  고객 id = 업체 id. D-91 상담 기록(`consults`)과 같은 줄에 저장해 옛 기록도 그대로 보인다.
- '고객 삭제' 는 **상담 기록 삭제**로 바꿨다 — 고객 운영 업체는 지우지 않는다.
- 원본의 예시 고객(정책자금 8곳)은 섞지 않는다. 연구소 샘플은 원본처럼 '샘플 넣어 보기' 단추로만.
- 원본에 없던 **업체 기록에 붙이기**를 원본 화면 안에 달았다: 연구소 월간 리포트·변경신고 기한(달력으로)·설립 가능성,
  정책자금 진단, 창업감면 판정.

### 일부러 옮기지 않은 것 (숨기지 않고 적는다)

- **모듈 잠금** — 대표 지시로 제외(D-91 그대로 둔다).
- 연구소 **PIN 화면 잠금** — OS 로그인이 맡는다. 신고시스템 **비밀번호 칸** — 비밀번호는 저장하지 않는다.
- 정책자금 **랜딩(마케팅) 화면** · '무료 체험' 안내 — 판매 페이지라 OS 안에 둘 이유가 없다.
- 원본 문구의 **"AI"** — 규칙 계산이라 'AI' 라 부르지 않는다(예: "AI 판단 근거" → "판단 근거").
- 연구소 **세액공제** 칸은 원본에 따로 된 화면이 없어 D-88 계산 화면을 그대로 둔다.

## 11. D-93 — 크레탑·영업·고용지원금도 원본 앱 화면 그대로 (2026-09-23)

대표 지시: "크레탑 분석기에 원래 비상장 주식 가치 평가랑 … 타겟으로 뭘 가져갈지, 어떤 컨셉으로 얘기할지 … 요약 기능 …
지금은 안 보이네. 다른 운영 OS들도 비슷비슷하게 뭔가 빠져 있는 거 아니야?"

### 왜 빠져 있었나

D-92 까지 옮긴 원본은 **각 저장소의 기본 가지(main)** 였다. 그런데
- 크레탑의 실제 분석 앱(개요·재무 상세·비상장 주식가치·미팅 제안·1장 요약)은 `corp-consult-sales-os` 의
  **다른 가지(`claude/cretop-mini-app`)의 `src/mini`** 에 있었다. main 에는 홈페이지용 분석기만 있었다.
- 영업 OS 와 고용지원금 Pro 는 화면이 **파일 하나(App.jsx 6천 줄 · SubsidyApp.jsx 7,414줄)** 에 몰려 있어,
  D-91/92 에서 기능을 골라 다시 짜는 동안 절반 넘게 빠졌다.

원본 화면 글자를 이 OS 코드와 대조해 잰 값(주석 뺀 한글 문자열 기준):

| 원본 | D-92 까지 | D-93 | 남은 것(일부러 뺀 것) |
| --- | --- | --- | --- |
| 크레탑 분석 앱(MiniApp·주식가치·상세 팝업·미팅 흐름) | 5% | **96%** (771/802) | 로그인·무료 체험 횟수·설문·관리자 승인 문구 |
| 영업 OS App.jsx | 52% | **98%** (1,801/1,820) | PIN 잠금 · 샘플 고객 · 브라우저 저장 안내 · 외부 SaaS 바로가기 |
| 고용지원금 Pro SubsidyApp.jsx | 30% | **97%** (1,215/1,242) | PIN 잠금 · 비밀번호 재설정 메일 · 샘플 10곳/26명 |
| 연구소 · 정책자금 · 창업감면 (D-92) | 92% · 84% · 98% | 그대로 | 로그인·PIN·랜딩 |

주의: 이 숫자는 "원본 글자가 이 OS 코드 안에 있느냐" 다. 원본 파일을 통째로 옮겼기 때문에 **화면에 나오지 않는
관리자·피드백·투어 글자도 코드에는 남아 있다**(쓰이지 않을 뿐). 화면에 뜨는지는 E2E·스크린샷으로 따로 봤다.

### 어떻게 옮겼나 (D-92 와 같은 방식)

- 원본 파일을 `orig/`(영업·고용지원금) · `mini/`(크레탑)에 **그대로 복사**하고, 바꾼 곳마다 `[D-93]` 을 적었다.
- 원본의 왼쪽 메뉴는 이 OS 모듈 목차가 대신한다. 원본 안에서 화면을 옮기면(예: '진행 보드 보기 →') **주소가 따라 바뀐다**
  — 뒤로 가기·새로고침·링크 공유가 된다.
- 저장은 모듈 기록(`module_data`) 한 곳. D-91/92 에 쌓인 기록(영업 상태 · 고용지원금 직원·업체 탭·달력 메모 · 지원금 켜고 끄기)을
  **처음 열 때 그대로 읽어 옮긴다**(지우지 않는다).
- 업체는 여전히 고객 운영 하나: 영업 '고객 등록', 고용지원금 '업체 추가' 는 **고객 운영 업체를 고르는 칸**이 됐다.
  고용지원금 엑셀 가져오기는 엑셀의 업체를 사업자번호·이름으로 고객 운영 업체에 맞추고, 없는 업체가 있으면 저장하지 않고 이름을 알려 준다.
- 고용지원금 업체 '삭제' 는 고용지원금 목록에서만 뺀다(기록은 남고, 다시 고르면 돌아온다). 고객 운영 업체는 그대로.
- 고용지원금 서류 파일: 클라우드 모드면 고객 운영 서류와 같은 보관함(`client-documents/워크스페이스/업체/employment/…`)에,
  이 브라우저에만 저장하는 모드면 원본처럼 기록 안에 담는다.
- 이 OS 에서 더한 화면은 남겼다: 고용지원금 **회차 일정 · 4대보험 명부 진단**(서류함 파일로 돌리기·업체 기록/달력에 붙이기),
  크레탑 **서류함에서 불러오기 · 1장 요약 복사 · 업체 기록에 붙이기**, 각 모듈 대시보드의 **고객 운영 업체와 연결**.

### 일부러 옮기지 않은 것

- 로그인·회원가입·무료 체험 횟수·구독/결제·관리자 승인·사용자 활동·베타 피드백 설문 — OS 로그인이 맡는다.
- **PIN 화면 잠금 · 비밀번호 재설정** — 이 OS 는 비밀번호·PIN 을 저장하지 않는다.
- **샘플 데이터**(영업 예시 고객 · 고용지원금 10곳/26명) — 실제 고객 운영 업체만 쓴다.
- 고용지원금 **첫 방문 자동 투어** — 원본 사이드바를 짚어 가는 투어라 이 OS 에서는 가리킬 곳이 없다.
- 모듈 잠금 — 대표 지시로 계속 제외.

## 12. D-94 — OS 안에서 자연스럽게 이어지게 (2026-09-23)

대표 지시: "기존 미래에이아이랩 운영 OS 내에서 사용하는데 불편함·어색함·자연스럽게 이어지지 못하는 부분 전면 체크 … 크레탑 하단이 가리고 연도가 ? … 남은 2% 도."

### 크레탑 (엔진은 한 줄도 안 바꿨다)
- 연도 '?' — 원인 둘: ① 이 OS 는 pdf.js 5 로 글자를 뽑았는데 엔진은 원본의 pdf.js 4 출력(제목이 '재 무 상 태 표' 처럼 띄어짐)에 맞춰져 있었다
  → 크레탑만 `pdfjs-dist-v4`(4.10.38) 로 되돌림. ② 연도 머리줄이 없는 표(제조원가·이익잉여금 등)는 엔진이 연도를 비워 둔다
  → 화면에서만 같은 보고서의 결산 연도로 채움(`mini/years.js`, 시험 8개). 알 수 없으면 채우지 않는다.
- 하단 탭 가림 — 바깥 상자의 `overflow-x:hidden` 이 스크롤 상자를 만들어 탭이 화면에 붙지 않았다 → `clip`. 휴대폰은 OS 하단 메뉴 위로.
- 올리면 바로 진단(같은 `buildResult`) · 탭은 주소 `?view=` · 원본 로고·제목·앱 안 뒤로/앞으로 → OS 머리줄 · ☰ → '☰ 분석 이력 N'.
- 핵심지표 검수·숫자 추출기가 방금 분석한 보고서로 시작 · 팝업 Esc·dialog · 저장 실패 알림 · 다른 회사 보고서 붙이기 확인.

### 남은 원본 문구·기능 (2~4%)
- 다시 대조해 남은 것은 로그인·PIN·비밀번호·샘플·관리자·랜딩·죽은 코드뿐 — 정책자금 `cases.ts` 는 원본에서도 쓰이지 않는다.
- 실제로 더한 것: 크레탑 저장 실패 알림 · 영업 백업 안내 · OS 백업에 모듈 기록(`axmvp.module.*`) 포함 · 연구소 현장조사 체크 저장(원본은 '데모 체크').
