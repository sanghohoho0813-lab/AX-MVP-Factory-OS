# 원본 OS 전부 옮기기 — 전체 지도와 순서 (D-91)

2026-09-23 · 대표 지시: "기존에 만들어 놓은 것들에서 **일부 기능만** 끌고 왔더라. **전부** 가져왔으면 좋겠다.
로그인 같은 것만 빼고 — 순수하게 눌렀을 때 어떻게 기능하고 어떤 결과가 나오는지. 왼쪽 목차도 똑같아야 한다.
그리고 이 OS 를 동료 컨설턴트에게 월 구독으로 팔 거다. 모듈은 내가 승인해 줘야만 열리는 구조로 간다."

## 0. 한 줄 요약

지금까지 옮긴 것은 **규칙 계산(엔진)** 이다. 원본의 **화면·업무 흐름·기록 관리**는 대부분 안 옮겼다.
원본 4벌의 화면을 합치면 **메뉴 47개 · 약 2만 줄**이다. 이것을 모듈 단위로 순서대로 옮긴다.

## 2. 무엇을 안 옮기는가 (대표 지시대로)

- 로그인·가입·초대코드·비밀번호 재설정 — 이 OS 는 이미 자체 인증이 있다.
- 결제·구독 PG(토스·Stripe) — 승인 상태만 관리하고 결제는 붙이지 않는다.
- PIN 화면 잠금 — 이 OS 에 이미 있고, 모듈마다 또 걸 이유가 없다.
- 외부 체험 게이트(`miraeailab.com/tool-gate.js`) — 우리 안에서 승인으로 대체한다.
- 원본에서도 안 쓰는 죽은 코드: 정책자금 `cases.ts`(238줄) · `DiagnosisForm.tsx`(502줄).
- 신고관리시스템 **비밀번호 저장 칸** — CLAUDE.md 금지 사항(평문 저장). 대신 "어디에 보관했는지" 메모만.

## 3. 목차(햄버거)를 어떻게 나누는가 — 결정

**OS 목차는 그대로 두고, 모듈 안에 2단 목차를 둔다.**

- 넓은 화면: 도구 화면 왼쪽에 모듈 목차가 한 칸 더 선다 (OS 사이드바 → 모듈 목차 → 내용).
- 휴대폰: 상단에 **모듈 햄버거**가 하나 더 생긴다. OS 햄버거는 그대로 왼쪽에 있다.
- 주소가 화면마다 갈린다: `/tools/employment/dashboard`, `/tools/employment/companies` …
- 모듈 목차는 `toolRegistry` 의 `sections[]` 하나로 정의한다 — 새 화면을 더하면 목차·주소·잠금이 따라온다.

**왜 OS 목차를 갈아끼우지 않는가**: (1) 모듈 안에서도 '오늘·고객 운영' 으로 한 번에 나가야 한다.
(2) 모듈을 따로 파는 구조에서 "이 모듈에 무엇이 들어 있는지" 가 목차로 보여야 판다.
(3) 목차가 통째로 바뀌면 대표가 지금 어디에 있는지 잃는다.

## 4. 모듈 잠금(구독) 구조 — 결정

- 모듈마다 상태 세 가지: **잠김 · 체험(기간) · 열림**. 대표(소유자)만 바꾼다.
- 잠긴 모듈도 **목차와 첫 화면은 보인다.** 눌러서 쓰려 하면 "대표 승인이 필요합니다" 가 뜬다 — 팔려면 보여야 한다.
- 기본(오늘·일정·고객 운영·서류함·업무 일기)은 늘 열린다. 잠금은 모듈에만.
- 결제는 붙이지 않는다. 상태만 관리하고, 나중에 결제를 붙일 자리만 비워 둔다.
- 저장: 로컬 모드는 브라우저, 클라우드 모드는 추가 전용 표 하나(`module_access`). SQL 은 써 두되 **대표가 실행**한다.

## 6. 업체·고객 데이터를 어떻게 합치는가 (중요)

원본들은 저마다 고객 명단을 따로 들고 있었다. 그대로 옮기면 **명단이 네 벌**이 된다.

- **업체(회사)는 이 OS 의 고객 운영 하나로 통일한다.** 모듈은 업체를 만들지 않고 고른다.
- 모듈만 쓰는 것(직원·연구과제·연구노트·리드·교육 기록 …)은 **모듈 데이터**로 따로 둔다.
- 모듈 데이터는 업체 id 를 물고 있는다 — 업체를 열면 모듈이 무엇을 쌓았는지 보인다.
- 원본의 고객 CSV 가져오기는 **고객 운영의 가져오기로 합친다**.

## 7. 지키는 것

- 규칙 계산은 원본 그대로. 화면만 이 OS 것으로.
- LLM 호출 0. 원본의 'GPT 프롬프트' 기능은 **프롬프트 글을 만들어 복사**하는 것이 전부였다 — 그대로 옮긴다.
- 주민등록번호·비밀번호는 저장하지 않는다. 명부 파일은 브라우저 안에서만 읽는다.
- DB 는 추가만. 모듈 데이터는 payload/추가 표로.
