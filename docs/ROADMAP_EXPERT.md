## 순서

1. ✅ **서류 자동 분류 정확도 (D-168 · D-181)** — PDF 줄 · 두 신호 일치 · 검증 사업자번호 · 두 서류 같은 값 · 재무제표 · 폴더 끌어다 놓기(D-168) · 대표 생년월일 · 인증서 유효기간 → 서류 만료 · 중소기업확인서 → 규모 · 발급일 버그(D-181) 끝
   - PDF 줄바꿈 살리기(pdf.js `hasEOL` · 줄 간격) → 제목 찾기 정상화. 파일 이름과 낱말 점수가 같은 서류를 가리키면 '확실' 로.
   - 폴더 끌어다 놓기(`webkitGetAsEntry`).
   - 두 서류가 같은 값을 말하면 자동 채움 · 사업자번호 검증 통과 OCR 은 사업자등록증 확실로.
   - 읽은 값 쓰기: 대표 생년월일 · 인증서 유효기간 → 서류 만료 · 재무제표 → 매출/영업이익 · 중소기업확인서 → 기업 규모.
2. ✅ **'검토함' 한 곳 (D-183)** — 새 화면 대신 이미 있는 '확인할 것'(D-158, 오늘 · 확인할 것 화면 · 업체 맞춤 추천)을 그 한 곳으로 키움: 기타 칸 옮기기(파일 이름 제안 · 모르면 고르기) · 겹친 서류 최신만 · 자동으로 넣은 중요 값 최종 OK(아니면 하나씩 다시 확인). 올리기 요약은 업체 기록에 남김(`docUploads`). '다시 분류 제안'(파일을 다시 읽어야 함)은 서류 탭 '서류 다시 분류' 그대로.
   - 🚨 기존 확인 화면들을 없애는 것은 대표 확인 뒤에만.
3. ✅ **추천을 맨 위에 · 크게 (D-190)** — 업체 상세 맨 위 '이 업체에 먼저 제안할 것 3가지'(가능성 · 한 줄 이유 · 열기 · 받으면 더 추천) · 고객 관리 카드에 추천 띠(휴대폰 접힌 카드에도 · 지원사업 n건 포함) · '추천 많은 순' 정렬 끝
4. ◐ **예상 금액 · 금액순 · 모자란 서류 → 요청 문구** — D-191: 엔진이 계산한 금액 표시 · 빠진 자료 → 요청 문구 끝. **금액 · 마감 순 정렬만 대표 확인 대기**. — 판정에 금액/근거/마감 붙이기(엔진이 이미 계산하는 값 재사용) · 금액 · 마감 순 정렬 · 'X 받기' 를 카톡/고객 화면 요청으로.
   - 🚨 추천 순서 기준이 바뀐다(판정 등급 → 금액 · 마감). 대표 확인 뒤에.
5. ◐ **상황 예시 카탈로그 (한 번 누르면 설계) (D-199)** — 절세 11 · 고용 4 · 연구소 2 · 창업감면 3 · 정책자금 3 = **23개 끝**(업체 상세 › 맞춤 추천 '상황 예시로 바로 설계' · 누르면 그 자리에서 업체 숫자로 설계 · 필요한 숫자 ✓/✗ · 빠진 것 요청 문구 · `?preset=` 로 모듈이 같은 가정으로 열려 바로 결과). **남은 것: 계산기 2(t7 특정법인 증여의제 · t8 불균등 유상증자/감자)** — 입력이 따로 있는 전문 계산기라 다음에.

7. **상황별 한 장 설계서** — 예: '청년 2명 채용' = 고용지원금 합계 + 세액공제 + 정책자금 힌트 + 추천 행동 → 업체에 붙이기.

## 콘텐츠 레이더 다음 단계 (D-194 뒤 · 아직 만들지 않음)

이번(D-194)은 **주제 고르기까지**. 최종 흐름: 시장 데이터 + 벤치마킹 + 내 채널 성과 + MIRAE 포지션 → 주제 10 → 3개 고르기 → 제목/썸네일 → 1개 → 구성 → 롱폼 대본 → 촬영 → 게시 → 성과 학습.

1. **내 채널 YouTube Analytics 연결(OAuth)** — 내 채널만 로그인 연결 → 노출 · 노출 클릭률(CTR) · 평균 시청 시간 · 평균 시청 비율. 이것이 있어야 '주제 문제인지 · 제목/썸네일 문제인지(CTR) · 대본 문제인지(시청 비율)' 를 나눌 수 있다. 지금은 공개 숫자만 — CTR · 시청 지속시간을 어림하지 않는다(화면에 '추후 연결 예정' 표시).
2. **AI 연결(대본)** — `ContentOpportunity → ContentBrief(radarStore.toContentBrief) → ScriptGeneration`. 브리프 모양은 이미 있다(주제 · 유형 · 시청자 · 관점 · 제목 · 썸네일 · 근거 · 참고 영상). 붙일 때도 경쟁 영상 제목 · 대사를 그대로 쓰지 않는 규칙 유지. (LLM 호출은 대표 결정 뒤에만 — 지금 0.)
3. **대본 구조 분석(합법적으로 확보한 것만)** — 사용자가 직접 넣은 자막/대본만 — 첫 15초 훅 · 문제제기 시점 · 숫자 사용 · 사례 등장 · 전환 문장 · CTA 구조. 남의 영상 자막을 자동으로 가져오지 않는다.
4. **썸네일 비전 분석** — 지금은 썸네일을 눈으로 비교만. 나중에 글자 크기 · 얼굴 · 대비 같은 구조만(별도 결정).
5. ◐ **성과 학습 (D-232)** — 올린 주소 ↔ 내 채널 영상(피드 안) · 주소 없으면 '이 영상인가요?'(제목 매칭 · 대표 확인) · '우리 채널 성과'(축 · 제목 틀 · 가장 잘 된 영상) 끝. **남은 것: 비중 가이드(레이더 추천 순서)에 되돌리기 · 7일/30일 숫자 저장**.
6. **Content Radar feedback loop**(D-195 에서 한 줄로만 남김 · YouTube Analytics 연결과 함께 제대로) — 게시 완료 → 실제 YouTube 주소 연결 → 7일 · 30일 성과 → 그때 추천했던 시장 신호(신호 세기 · 근거)와 실제 성과를 나란히.
