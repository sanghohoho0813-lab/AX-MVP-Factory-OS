# SPACENOTE 벤치마킹 → 미래AI랩 OS 제품·UX 개발 기준서

> **문서 성격:** Claude Code에 전달하는 **독립 실행형 참고 명세서**. 스페이스노트의 디자인·기능을 복제하라는 지시가 아니다. 스페이스노트 소개 영상의 **업무 흐름과 인터랙션 패턴을 미래AI랩의 컨설턴트 업무에 맞게 재해석**하는 기준이다.
>
> **작성 기준일:** 2026-11-03 / **참조 OS:** `sanghohoho0813-lab/AX-MVP-Factory-OS`의 최신 `main` 코드(분석 당시 D-511 계열 커밋 포함). **실제 영상 근거:** 사용자가 공유한 스페이스노트 소개 화면 녹화 5개에서 확인되는 1~7편의 시연 화면·목차. 홍보 영상의 기능은 **시연된 화면/홍보 설명**이지 프로덕션 안정성이나 매출을 검증한 사실은 아니다.
>
> **중요:** 영상 없이도 이 MD만으로 작업 방향을 이해할 수 있도록 작성했다. 불명확한 세부 구현은 추측하지 말고 현행 코드로 검증한다.

## 0. 한 줄 제품 전략

**스페이스노트는 '현장/프로젝트 하나를 중심으로 관련 업무를 이어주는' 제품 패턴이 강점이다. 미래AI랩은 '고객사 하나를 중심으로 컨설팅·서류·일정·마케팅을 연결하는' SaaS가 되어야 한다.**

첫 판매 고객은 **중소기업·정책자금 컨설턴트(개인 및 소규모 팀/사업단)**. 최초 유료 상품은 아래 네 영역만 전면에 둔다.

1. **마케팅·브랜딩**: 브랜드별 AI, 트렌드/주제, 스레드·숏폼·유튜브·블로그 등 콘텐츠 작성, 초안 저장·재사용, 발행계획 및 성과.
2. **고객사 운영**: 고객 기록, 상담 이력, 진행상태, 담당자, 후속 연락.
3. **서류**: 안전한 업로드/보관, 문서 자동 분류, OCR, 검증·누락·유효기간 관리.
4. **일정·업무**: 오늘 할 일, 상담 일정, 정책자금 등 마감, 알림, 담당업무.

특허·벤처·정책자금 심화·세무/재무·AX 스튜디오 등은 **기존 코드와 데이터는 보존**하고 단계별 완성도 검증 후 **추가 구독 모듈**로 출시한다. 카드뉴스는 1차 상품에서 노출하지 않는다.

## 1. 스페이스노트 소개 영상 7편 — 확인된 화면과 차용할 원칙

| 편 | 영상에서 확인되는 흐름 | 차용할 원칙 | 미래AI랩 적용/제외 |
|---|---|---|---|
| **1. 시작하기와 기본 설정** | 회사 정보 단계별 등록(사업자번호 등), 조직/직원 설정, 초대·권한, 메뉴/사용 모듈 구성, Workspace 대시보드, 일정 등록, 모바일 모습 | **가입 직후 첫 가치 경험까지 유도**, 계정/조직에 맞는 메뉴 | 온보딩: 브랜드 설정 → 첫 고객사 → 서류 한 장 → 업무 추천; 기존 초대 UI 재사용 |
| **2. 프로젝트와 현장관리** | 프로젝트 등록, 좌측 프로젝트 목록과 우측 상세, 공정/진행률, 프로젝트 일정, 현장 공사일보, A/S 등록·진행, 안전 관련 기록 | **하나의 업무 항목에 상태·기록·담당자·일정이 붙음** | 프로젝트=컨설팅 신청건/수행건. 예: 진단→자료 요청→검토→신청→보완→결과→사후관리. 공사 공정·A/S 자체는 제외 |
| **3. 출퇴근·인력·급여** | 모바일 출퇴근, 출퇴근 기록, 연차 신청·승인, 급여/노무 현황, 일용직 관리 | **현장에서 입력한 데이터가 정산·승인까지 연결** | 출퇴근/GPS/급여는 1차 제외. 승인 이력과 입력→후속 처리의 연결 방식만 참고 |
| **4. 견적·구매·실행결산** | 견적서 작성/수정 및 PDF, 발주/구매, 진행·실행결산, 비교 분석 | **계약→진행→수입/비용 데이터를 한 업무의 맥락에서 관리** | 컨설팅 계약·착수금·성공보수·청구/입금 상태로 번역. 건설 원가·자재 관리 기능 복제 금지 |
| **5. 자금·금융데이터** | 매출/수금 관리, 거래명세서, 현금흐름/가용자금, 지급/수금 현황, 세금계산서·금융데이터를 다루는 화면 | **돈의 흐름을 목록·예외·기한으로 읽기 쉬움** | 미수수수료·청구기한·결제 상태 정도만 선별. 은행·회계·세금계산서 전면 실시간 연동은 1차 범위 제외 |
| **6. 소통·결재·협업** | 업무 맥락별 대화, 채팅 목록/대화창, 결재 작성, AI를 활용한 문서 작성, 일정/협업 화면, 솔챗 형태의 소통 | **대화의 목적이 실제 업무 처리** | 먼저 고객사/업무별 댓글·@멘션·변경 이력·업무 배정. 실시간 종합 메신저·전자결재는 수요 검증 후 |
| **7. AI와 업무 자동화** | 회의록 업로드→AI 문서 생성, AI 연결(MCP) 메뉴, Claude/ChatGPT/Cursor 등 연결 안내, 질문→현장 일정·업무 요약, 거래처 일괄 등록, 출력/이메일/알림 연계 시연 | **AI가 저장된 업무 정보를 조회·요약하고 실제 작업으로 이어짐** | 기존 OS 내부 AI와 별개로 외부 MCP용 안전한 읽기 API를 장기 설계. 자동 수정/삭제는 제한 |

**영상 해석 유의:** 영상의 내용은 관찰 가능한 UI와 제작자가 설명한 사용 시나리오를 요약한 것이다. 실제 연동의 안정성, 보안감사, SLA, 실사용률 등은 검증하지 않았다. 보이지 않은 기능을 임의로 '완성'이라고 평가하지 않는다.

## 2. 화면·UX 패턴 상세 — 스페이스노트에서 배울 것

### A. 정보 구조(IA)

- 왼쪽 내비게이션으로 업무 영역을 구분하고, 상단에는 현재 맥락/주요 액션을 둔다.
- **목록 → 선택한 상세 → 즉시 처리할 액션**이 같은 화면에서 이어지는 패턴이 보인다. 데스크톱에서는 목록+상세 동시 보기, 모바일에서는 별도 단계 화면으로 전환한다.
- 프로젝트, 회의록, A/S, 일정 등 서로 다른 화면에서도 **비슷한 버튼 배치·상태 표시·폼 패턴**을 반복한다.
- 회사/역할/업무에 따라 쓰지 않는 메뉴가 처음부터 펼쳐져 있지 않도록 한다.

**미래AI랩 규칙:** 첫 내비게이션에서 1차 상품 네 영역을 핵심으로; 전문 모듈은 '추가 모듈 / 출시 예정'으로 분리. 메뉴가 늘어도 1차 사용자 첫 화면의 길이와 복잡도는 늘리지 않는다.

### B. 상태·다음 행동

- 단순 '자료 있음/없음' 대신 `접수됨 → 분석됨 → 확인 필요 → 확인 완료`처럼 **상태를 나눈다**.
- 고객사 컨설팅 건은 `준비 → 진행 → 고객 응답 대기 → 검토 → 접수/제출 → 완료/사후관리`를 업무에 맞게 표준화한다. 세부 상태는 업무별 차이를 존중하되 공통 표시 규칙을 사용한다.
- 다음 행동은 해당 항목에서 바로 **담당자 지정, 기한 설정, 서류 요청 문구 생성, 업무 생성**으로 연결한다.
- 표/카드의 강조색은 의미 있는 상태에만 사용한다. 경고/완료/대기/마감일을 중복 색상으로 과장하지 않는다.

### C. 폼·대시보드

- 등록 폼은 항목이 많더라도 **필수 최소 항목→선택 정보→추후 보완** 순서로 단계화한다.
- 첫 화면은 '오늘 해야 할 것' 중심. KPI 숫자만 잔뜩 나열하지 않고 **클릭하면 바로 해결되는 작업**을 보여준다.
- 정보 반복, 중첩 박스, 비슷한 버튼 여러 개, 설명서가 없으면 이해하기 어려운 전문 용어를 줄인다.
- 대시보드 구성과 표시/숨김 설정은 PC·모바일에서 동기화하되 사용자가 의도적으로 꾸민 설정을 존중한다.

### D. 모바일

- 모바일에서 목록/상세/등록 폼이 가로로 넘치지 않아야 한다(검수 기준: 390px).
- 주요 터치 요소의 조작 영역은 가능하면 44px 이상.
- '고객 연락/서류 확인/오늘 일정/미팅 메모/콘텐츠 이어 쓰기'를 모바일 상위 동선으로 둔다.
- 오프라인·저속 네트워크·동기화 실패 시 입력값을 잃지 않고 상태를 명확히 안내한다.

## 4. 미래AI랩에 맞게 번역한 대표 업무 5가지

### 시나리오 A — 신규 고객사 등록

1. 컨설턴트 신규 가입/로그인 → 브랜드 정보 최소 입력.
2. 고객사 추가에서 회사명/사업자번호 입력 또는 사업자등록증 업로드.
3. 문서 자동 분류·검산·정보 추출. 확실한 정보만 자동 입력, 의심스러운 값은 확인.
4. 고객사별 서류함/할 일/상담 메모/진행 건으로 이어짐.
5. 사용자는 **'지금 무엇을 준비할까요?'**와 다음 1~3개 실무 행동을 받음.

### 시나리오 B — 정책자금 신청건 진행

1. 고객사에서 '중진공 신청건' 생성(또는 기존 진행 이력과 연결).
2. 신청 마감·담당자·필요 서류 목록 설정.
3. 서류 업로드 후 실제 접수/분석/검토 상태가 구분됨.
4. 누락 서류는 발급처를 포함한 요청 문구 자동 초안 → 사용자가 복사·전달.
5. 기한이 지나거나 고객 회신이 없으면 후속 업무/알림. 제출과 승인 여부는 실제 증빙 없이 자동 확정 금지.

### 시나리오 C — 고객사 미팅 이후

1. 오늘 일정에서 고객사를 열어 기존 서류·상담 요약을 확인.
2. 상담 중 사실/가정/제안과 다음 약속을 구분해 기록.
3. 명시적 확인 뒤 고객사 사실 창고·업무·날짜에 연결.
4. 팀 이용 시 담당 팀원에게 할 일 배정; 변경 흔적을 남김.

### 시나리오 D — 마케팅 콘텐츠 제작

1. 고객별 브랜드/타깃/말투 설정 → 이번 주 주제 추천.
2. 콘텐츠 생성·검토·수정 → 클라우드 초안 저장.
3. 다른 기기에서 이어 쓰기 → 발행 계획 → 수동 성과 기록 또는 승인된 연동으로 성과 수집.
4. AI가 사실·정책금액·지원요건을 만들어 내지 않도록 공식 근거/확인 필요를 구분.
5. 고객사의 민감한 서류·재무·개인정보는 **명시적 동의/가공/익명화 절차 없이 공개용 콘텐츠에 넣지 않음**.

### 시나리오 E — 사업단 협업(초기 유료 고객 수요 확인 후)

1. 사업단장/관리자가 조직 요금제를 이용하고 팀원을 초대.
2. 구성원 역할과 **고객사별 접근 권한**을 분리.
3. 상담 건에 담당자 지정·댓글·@멘션·진행상태 이력.
4. 팀원이 퇴사/이동하면 기존 고객·서류 접근을 즉시 차단하고 업무를 재배정.
5. 회사 전체 메신저, 읽음 표시, 푸시, 전자결재는 파일럿 수요가 확인될 때 별도 도입.

## 6. MCP: 외부 LLM 연결은 '별도 제품 기능'으로 관리

**구분:** 현재 OS의 `내부 화면 → LLM API`와 미래의 `외부 Claude/ChatGPT → MCP 서버 → OS`는 다르다. 기존 AI에 MCP를 붙였다고 자동으로 안전한 외부 데이터 접근이 가능한 것은 아니다.

권장 단계:

1. **읽기 전용:** 본인에게 허용된 고객사 이름/기본 상태/할 일/마감·누락 서류 **요약 정보만** 조회. 원문 서류 다운로드는 기본 제공하지 않음.
2. **요약·초안:** 조회 결과로 주간 보고서·서류 요청/상담 준비 초안을 작성(실제 보내기는 사용자).
3. **승인 후 제한적 쓰기:** 할 일 생성, 상담 기록 저장 등은 변경 내용을 보여주고 사용자 승인 뒤 실행.
4. **최종 단계:** 범위/정책/비용을 검증한 뒤 MCP 외부 공개. 전문 모듈/고객 전체 데이터는 디폴트 차단.

필수 통제: 사용자 인증·OAuth/위임 범위·워크스페이스 및 고객사별 권한 재검사·민감정보 최소화·요청별 감사 로그·연결 해제·요청 제한·오류 시 차단(fail closed). **MCP 연결 수단을 먼저 만들기보다 '어떤 데이터를 내줘도 되는지'를 먼저 설계**한다.

## 8. UX 검수 기준 (모든 단계 공통)

- **완료 중심:** 메뉴를 찾기 쉽게 하는 것뿐 아니라 실제 업무 완료까지의 클릭·입력 수를 측정한다. '핵심 업무 3클릭 이내 착수'를 목표로 하되 실측 없이 달성 선언 금지.
- **텍스트:** 처음 보는 컨설턴트도 이해할 쉬운 한국어. 설명은 간단히, 자세한 이유는 접어서 제공. 같은 설명 세 번 반복 금지.
- **레이아웃:** 데스크톱/태블릿/390px 모바일에서 정보 우선순위·터치·가로 넘침 점검. 큰 글자 설정에서도 정상.
- **상태:** 빈 화면·저장 중·저장됨·저장 실패·권한 없음·구독 만료·AI 한도 초과를 명확히 안내.
- **연속성:** PC↔모바일, 새로고침, 로그인 재진입, 다중 작업공간 전환 시 결과·초안 보존.
- **중복 제거:** 같은 고객/서류/업무/브랜드 프로필의 별도 원본을 늘리지 않는다(SSOT).
- **보안:** 대표용/내부 팀장용/구독 고객용 기능의 분리와 RLS 검증, 고객별 파일 권한, 외부 AI 반환 텍스트의 개인정보 검증.
- **테스트:** 단위/e2e/RLS/실계정 중 무엇을 확인했고 무엇을 못 했는지 명시. 영상에 보였다는 이유만으로 UI 복제 완료 선언 금지.

## 9. Claude Code의 실행 규칙 — 마스터 지침과 같이 사용

이 문서는 **벤치마킹 제품 명세서**, `docs/PRODUCT_MASTER_PLAN.md`는 **미래AI랩 개발의 최종 기준·진행 상태**로 사용한다.

처음 실행할 때:

1. 최신 `main`, `docs/PRODUCT_MASTER_PLAN.md`(있다면), `docs/SAAS_ROADMAP.md`, 실제 관련 컴포넌트를 읽고 기존 기능과 미구현을 비교한다.
2. 이 문서의 아이디어를 **`이미 있음 / 보완 필요 / 출시 전 필수 / 후순위 / 범위 밖`**으로 분류하고 근거 파일 경로를 남긴다.
3. 주요 제품 규칙과 검수 기준을 마스터 플랜에 반영하고, **단계별 P0·P1·P2 작업 목록**과 선행 관계를 작성한다.
4. 한 번에 전부 개발하지 않는다. 가장 중요하고 테스트 가능한 **한 묶음**만 실제 구현·검증·기록한다.
5. 이후 사용자가 **“마스터 개발계획 기준으로 다음 단계 고도화해 줘”**라고 하면 현재 계획·최신 코드를 재확인하여 다음 미완료 한 묶음을 자율 선택한다.
6. 매 회차 요약에는 `변경 기능 / 사용자 효용 / 변경 파일 / 테스트 실제 결과 / 미검증·남은 위험 / 다음 단계`만 간결히 보고한다.

**변경 승인 필요:** 운영 DB/권한 체계, 결제·과금, 고객 데이터 삭제, 외부 API 추가 및 비용, 생산환경 보안정책. 코드만 작성하는 것과 운영에 적용하는 것을 반드시 구분한다.

## 10. 절대 금지

- 스페이스노트의 화면·문구·소스코드를 그대로 복제하거나 특정 업체 고유 디자인을 카피하지 않는다.
- 기존 대표 OS의 기능·데이터·설정·기존 고객 업무를 훼손하지 않는다.
- 현재 검증된 코드를 조사하지 않고 이름만 다른 신규 버전으로 중복 개발하지 않는다.
- 고객사 비공개 자료를 공개 마케팅 결과, 외부 MCP 응답, 다른 팀의 화면에 무단 포함시키지 않는다.
- 중요 서류/OCR/AI 추론을 사용자 확인 없이 사실로 확정하거나 임의로 덮어쓰지 않는다.
- UI만 보기 좋게 고치면서 업무 동선을 늘리거나 주요 상태를 숨기지 않는다.
- 완성도 낮은 전문 모듈·채팅·MCP를 1차 판매 범위에 끼워 넣지 않는다.
- 실제 운영 검증 없이 보안/결제/백업/모듈 출시를 완료했다고 주장하지 않는다.
