## 2. 공통 규약 (모든 도구가 같은 방식으로)

- **자리**: `src/tools/<key>/` 안에 원본 규칙(`lib/`·`engine/`)과 화면(`<Key>Page.tsx`)을 함께 둔다. 규칙 파일은 원본 그대로, 화면만 이 OS 것.
- **목록**: `src/config/toolRegistry.ts` 한 줄. `live`(사이드바에 걸림) · `review`(도입 검토중 한 줄 아래) · `planned`(누를 수 없음).
- **저장**: 입력값은 `axmvp.tools.<key>` 로 이 브라우저에만. 백업에 안 들어간다(참고용 입력이라서).
- **업체에 붙이기**: 모든 결과 화면에 같은 단추 `업체 기록에 붙이기`. 업체 레코드의 `toolResults[]` 에 들어간다(payload → **마이그레이션 없음**). 활동 기록에 `tool` 한 줄. 업체 상세 개요에 '도구 결과' 칸.
- **고객 플랫폼**: 붙일 때 '고객 플랫폼에 요약도 발행' 을 켜면 연결된 고객 계정이 있을 때만 `portal_updates`(category `result`)로 **요약 글만** 나간다. 입력값·수수료·내부 메모는 안 나간다. 발행한 update id 를 결과에 기억해 두 번 발행하지 않는다.
- **말투**: 전부 비단정. "AI" 라고 부르지 않는다. 승인·인정·감면을 보장하는 문장이 없다.

## 3. 홈페이지(고객 플랫폼)와의 관계

- 홈페이지와 이 OS 는 **같은 Supabase 프로젝트**를 쓴다(홈페이지 `docs/CUSTOMER_DATA_CONTRACT.md` 가 이 저장소의 `customer_bridge.sql` 을 정본으로 가리킨다).
- 홈페이지의 `tools` 표에는 `cretop-analyzer` 카드가 아직 옛 배포 주소(corp-sales-os …/mini.html)를 가리킨다. 이 OS 안에 분석기가 들어왔으니 **그 카드는 내부용으로 바꾸거나 내리는 것이 맞다** — 홈페이지 저장소는 이번에 손대지 않았다(대표 확인 필요, §5).
- 고객이 보는 것은 여전히 `portal_*` RPC 뿐이다. 이번 작업으로 새 RPC·새 표는 없다.

## 5. 확인하지 못한 것 · 대표 판단이 필요한 것

- ~~고용지원금의 엑셀(xlsx) 명부는 읽지 못한다~~ → **D-89 에서 읽는다.** 다만 오래된 `.xls`(2003 이전),
  암호가 걸린 파일, 수식만 있고 값이 저장되지 않은 파일은 못 읽는다 — 그때는 CSV 로 저장해 달라고 안내한다.
- 홈페이지 `tools` 카탈로그의 크레탑 카드는 **아직 그대로다.** 조사해 보니 그 주소는 고객 화면에 노출되지
  않는다(홈페이지가 `external_url` 을 조회에서 빼고 권한 확인 뒤에만 건넨다 — `src/lib/portal.ts`).
  무엇을 어떻게 바꿀지는 `supabase/homepage_tools_catalog.sql` 에 실행하지 않은 SQL 로 적어 두었다.
  카드를 화면에서 내리려면 홈페이지 코드(`src/data/tools.ts`)도 함께 고쳐야 한다 — 그 저장소는 이번에도 손대지 않았다.
- 영업 도구의 가격표는 원본 값 그대로다. 실제 가격 정책과 맞는지는 대표가 본다.
- 정책자금의 한도·금리·보증료는 원본에도 없어서 여기에도 없다.
- 크레탑은 OCR 을 하지 않는다. 스캔본 PDF 는 원문을 붙여넣어야 한다.
