# Supabase 연결하기

지금은 데이터가 **이 브라우저에만** 저장됩니다. Supabase를 연결하면:

- 휴대폰·다른 PC에서도 같은 데이터를 봅니다
- 사업자등록증 같은 **파일을 실제로 첨부**할 수 있습니다
- 데이터가 서버에 안전하게 보관됩니다 (방문기록을 지워도 사라지지 않음)

아래 순서대로 하시면 됩니다. **30분 정도** 걸립니다.

---

## 1단계 — Supabase 프로젝트 만들기

1. https://supabase.com 접속 → 로그인(GitHub 계정으로 가능)
2. **New project** 클릭
3. 입력값
   - **Name**: `ax-factory-os` (아무거나 괜찮습니다)
   - **Database Password**: 아무 비밀번호나. **어딘가 적어두세요** (나중에 필요할 수 있음)
   - **Region**: `Northeast Asia (Seoul)` 선택 ← 한국이라 이게 제일 빠릅니다
4. **Create new project** → 2~3분 기다립니다

> ⚠️ 이 프로젝트는 **이 시스템 전용**으로 새로 만드세요. 다른 서비스에 쓰던 프로젝트를 같이 쓰지 마세요.

---

## 2단계 — 표(테이블) 만들기

1. 왼쪽 메뉴 **SQL Editor** → **New query**
2. 이 저장소의 **`supabase/SETUP.sql`** 파일 내용을 **전부 복사**해서 붙여넣기
3. 오른쪽 아래 **Run** 클릭
4. `Success. No rows returned` 가 뜨면 성공입니다

> 여러 번 실행해도 안전합니다. 이미 만들어진 것은 건너뜁니다.

---

## 3단계 — 연결 정보 두 개 복사하기

1. 왼쪽 메뉴 맨 아래 **Project Settings**(톱니바퀴) → **API**
2. 두 값을 복사해 둡니다
   - **Project URL** — `https://xxxxxxxx.supabase.co` 형태
   - **공개 키** — `sb_publishable_...` 또는 `eyJ...` 로 시작하는 긴 글자

> ⚠️ **가장 많이 하는 실수**: 브라우저 주소창에 있는 대시보드 주소를 넣는 것입니다.
>
> | | 값 |
> |---|---|
> | ❌ 틀림 | `https://supabase.com/dashboard/project/abcdefgh` ← 브라우저 주소창 |
> | ✅ 맞음 | `https://abcdefgh.supabase.co` ← Project Settings > API 의 Project URL |
>
> 뒤쪽 영문자(`abcdefgh`)는 같습니다. 앞뒤 형태만 다릅니다.

> 🔒 **주의**: 같은 화면에 있는 **`service_role`** 키는 **절대 쓰지 마세요.** 그건 모든 보안을 무시하는 마스터 키입니다.
> `anon public` 키만 씁니다. 이 키는 원래 브라우저에 공개되는 값이고, 위에서 만든 보안 규칙(RLS)이 데이터를 지킵니다.

---

## 4단계 — Vercel에 연결 정보 넣기

1. https://vercel.com 접속 → 이 프로젝트(`ax-mvp-factory-os`) 선택
2. **Settings** → **Environment Variables**
3. 아래 3개를 추가합니다. 각각 **Production / Preview / Development 전부 체크**

   | Name | Value |
   |---|---|
   | `VITE_DATA_MODE` | `supabase` |
   | `VITE_SUPABASE_URL` | 3단계에서 복사한 Project URL |
   | `VITE_SUPABASE_ANON_KEY` | 3단계에서 복사한 anon public 키 |

4. **Save**
5. **Deployments** 탭 → 맨 위 배포의 `⋯` → **Redeploy** 클릭
   (환경변수는 다시 배포해야 반영됩니다)

---

## 5단계 — 계정 만들고 워크스페이스 만들기

1. 배포가 끝나면 https://ax-mvp-factory-os.vercel.app/ 접속
2. 이제 **로그인 화면**이 뜹니다 → **회원가입**
3. 이메일·비밀번호 입력 → 메일함에서 **인증 메일 확인**
4. 로그인하면 **워크스페이스 만들기** 화면이 나옵니다 → 이름 입력 (예: `AX랩`)
5. 완료 — 이제 고객 운영 화면이 열립니다

---

## 6단계 — 지금 브라우저에 있는 데이터 옮기기

**중요**: Supabase로 바꾸면 처음엔 비어 있습니다. 지금까지 입력한 내용을 옮기세요.

### 옮기기 전 (아직 local 모드일 때)

1. 지금 쓰던 브라우저에서 https://ax-mvp-factory-os.vercel.app/ 접속
2. 고객 운영 현황 → **`백업 내려받기`** 클릭
3. `client-ops-backup-YYYY-MM-DD.json` 파일이 저장됩니다

> 4단계(Vercel 설정)를 하기 **전에** 먼저 받아두세요. 설정 후에는 local 데이터에 접근하는 화면이 안 나옵니다.

### 옮긴 뒤 (supabase 모드로 로그인한 상태)

1. 고객 운영 현황 → **`백업 불러오기`** → 받아둔 JSON 파일 선택
2. 물어보면 **[확인] 합치기** 선택
3. 고객 목록이 그대로 올라옵니다

## 잘 됐는지 확인하는 법

- 로그인 화면이 뜬다 → 연결 성공
- 오른쪽 위 저장 표시가 **"로컬 데모 · 이 브라우저에만 저장"** 이 아니라 **클라우드 저장**으로 바뀝니다
- 설정 → 시스템 에서 **데이터 모드: 클라우드(supabase)** 로 보입니다
- 휴대폰에서 같은 계정으로 로그인 → 같은 고객 목록이 보이면 완전히 성공

## 안 될 때

| 증상 | 원인 | 해결 |
|---|---|---|
| 설정 오류 화면이 뜬다 | 환경변수 이름 오타 | `VITE_` 로 시작하는지, 3개 다 넣었는지 확인 |
| 여전히 로컬 모드다 | 재배포를 안 함 | Vercel → Deployments → Redeploy |
| 로그인은 되는데 저장이 안 된다 | SQL 미실행 | 2단계 `SETUP.sql` 다시 실행 |
| 파일 첨부가 안 된다 | Storage 버킷 없음 | 2단계 SQL에 포함돼 있음. 다시 실행 |
| 회원가입 메일이 안 온다 | 스팸함 | Supabase → Authentication → Users 에서 직접 확인 가능 |

## 참고 — 보안 요약

- 브라우저에는 **anon 키만** 들어갑니다. `service_role` 키는 어디에도 쓰지 않습니다.
- 모든 표에 **RLS(행 단위 보안)** 가 걸려 있어, 로그인한 사람이 속한 워크스페이스의 데이터만 읽고 씁니다.
- 첨부 파일은 **비공개 버킷**에 저장되고, 볼 때마다 5분짜리 임시 링크를 만들어 씁니다.
- 공동인증서 비밀번호·주민등록번호는 **저장하지 않습니다**.
