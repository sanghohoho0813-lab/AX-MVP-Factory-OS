# 고객성장관리(My MIRAE) — 운영 적용 · 되돌리기 · 매일 쓰는 법 (D-681)

> 운영 DB 변경 · 운영 배포 · 외부 발송은 **대표 승인 뒤에만**. 이 문서는 승인 뒤 그대로 따라 하는 순서다.

## 1. 지금 상태

| 무엇 | 어디 | 운영 |
|---|---|---|
| DB 0033 | `supabase/migrations/20261127000033_customer_growth.sql` | **아직 안 넣음** |
| 내부 OS | 작업 브랜치 `claude/ax-mvp-factory-os-stage-1-dcf98c` | main 병합 전(승인 뒤 fast-forward) |
| 홈페이지 | 기능 브랜치 `claude/customer-growth-portal-p0` | main 병합 전(승인 뒤) |

**순서가 바뀌어도 안전하다**: 두 앱 모두 0033 이 없으면 새 칸을 숨기고 예전 화면 그대로 둔다(qa:growthportal W11 이 진짜 DB 로 확인).
0033 을 먼저 넣어도 예전 앱은 새 함수를 부르지 않으니 아무것도 안 바뀐다.

## 2. 운영 적용(대표가 하는 일 · 약 5분)

1. **먼저 넣을 것 확인** — 0006 · 0016 · 0023 · 0026 이 들어가 있어야 한다(0026~0032 는 2026-11-26 적용 확인됨). 0033 파일 맨 위가 스스로 확인하고, 빠졌으면 아무것도 바꾸지 않고 멈춘다.
2. Supabase › SQL Editor 에 `supabase/migrations/20261127000033_customer_growth.sql` **통째로** 붙여 실행. 한 덩어리(begin … commit) — 중간에 실패하면 아무것도 안 들어간다.
3. 같은 곳에 `supabase/manual/verify_after_0033.sql` 실행(읽기만) → 1~6번 줄이 모두 **'좋음'**. 7 · 8번은 안내(처음엔 0).
4. 내부 OS main 병합(fast-forward) → Production. 홈페이지 기능 브랜치 main 병합 → Production.
5. 확인: 대표 계정으로 업체 상세 › 고객 플랫폼 탭에 '고객에게 보낸 보고서' 칸이 보이면 켜진 것.

## 3. 되돌리기(문제가 보이면 · 1분)

- Supabase › SQL Editor 에 `supabase/manual/rollback_0033.sql` 실행 → 마지막 줄 `false | false | false`.
  하는 일: 0033 함수 11개 실행 권한 · 두 표 읽기 권한만 거둔다. **표 · 보고서 · 열람 기록 · 함수 본문은 지우지 않는다.**
  두 앱은 그 순간부터 새 칸을 숨기고 예전 화면 그대로(앱을 되돌릴 필요 없음).
- 다시 켜기 = 0033 파일 통째로 다시 실행(기록은 그대로 돌아온다 — W11d).
- 앱 코드까지 되돌려야 하면: OS 는 main 의 D-681 커밋을 되돌리는 새 커밋(강제 push 금지) · 홈페이지도 같은 방식.

## 4. 대표 · 팀장의 하루(쓰는 법)

1. **오늘** 머리 줄의 **'고객 화면 챙길 것 n'** 칩 → 업체마다 한 줄(가입 안내 뒤 3일 · 첫 방문 없음 3일 · 보고서 안 열어 봄 3일 · 경과 보고 14일 공백 · 30일 안 오심) → 누르면 그 업체 고객 플랫폼 탭.
2. 업체 상세 › **고객 플랫폼** 탭 → [보고서 만들기] → 종류 · 기간 → [초안 만들기] → 줄 켜고 끄기(내부 글은 꺼진 채) · 한마디 → [고객 화면으로 보기] → [고객 화면에 발행] → **안내 문구 복사 → 카톡으로 보냄**(앱은 보내지 않는다).
3. 다음 날 같은 탭에서 계정마다 '열어 봄 · 확인' 을 본다. 안 열었으면 3일 뒤 오늘 칩에 뜬다. 고객 문의는 같은 탭 '고객이 보낸 요청' 에.
4. 잘못 적었으면 [정정](고친 곳 한 줄 — 고객에게 보임) · 내려야 하면 [내리기](까닭은 내부에만).

## 5. 시범 고객 3~5곳에 붙이는 법

1. 고객에게 홈페이지 회원가입을 부탁한다 — 업체 상세 › 고객 플랫폼 › **[가입 안내 문구]** 복사 → 카톡 → **[보냈어요]**(3일 지나도 연결이 없으면 오늘 칩에 뜬다).
2. 고객이 가입하면 그 이메일로 **[연결]** — 대표(full)만 연결할 수 있다. 같은 회사 직원이 따로 보려면 그 사람 이메일로 한 번 더 연결(계정마다 기록이 따로).
3. 고객에게 보이는 단계 · 프로젝트명 확인 → 첫 경과 보고 발행(지난 2주 또는 올해) → 안내 문구 전송.
4. 첫 주: 고객이 '열어 봄 · 확인' 했는지 · 문의가 들어오는지 본다. 고객이 끊고 싶어 하면 그 계정 줄 [잠시 멈춤] · [연결 끊기] — 서버가 그 순간부터 막는다.
5. 고객 쪽 말: "보고서 아래 [확인했어요] 는 읽었다는 표시예요. 계약 검수나 대금 승인이 아니에요."

## 6. 승인이 필요한 것(대표만)

- 운영 DB 에 0033 넣기(위 2-2) · main 병합 두 곳 · 시범 고객 선정 · 고객에게 보내는 첫 안내.
- 알림톡 · 메일 자동 발송(비용 · 외부 발송) — P1 이후 따로 묻는다.
