## 2. 운영 적용(대표가 하는 일 · 약 3분)

**한 번에 넣기(D-689 · 권장)** — 네 파일을 번갈아 붙이지 않고 한 장으로.

1. Supabase › SQL Editor 에 `supabase/manual/check_applied_0033_0036.sql` **통째로** 붙여 실행(읽기만) → 네 줄(0033 · 0034 · 0035 · 0036)이 지금은 **'없음'**.
2. 같은 곳에 `supabase/manual/apply_0033_0036_all.sql` **통째로** 붙여 실행 → 맨 아래 결과 표 네 줄이 모두 **'들어감'**.
   - 한 거래다 — 중간에 하나라도 멈추면 네 개 모두 들어가지 않는다(잠금이 5초 넘게 걸려도 멈춘다 → 조금 뒤 다시).
   - 먼저 있어야 하는 것(0006 · 0016 · 0023 · 0026 — 0026~0032 는 2026-11-26 적용 확인됨)이 빠졌으면 그 자리에서 멈추고 아무것도 바꾸지 않는다.
   - 여러 번 실행해도 같다. 이미 0033 이나 0034 · 예전 세 개 묶음(`apply_0033_0035_all.sql`)을 넣었어도 된다(먼저 넣은 '기록을 남기기 시작한 때' 를 덮지 않는다).
   - 더하기만 한다. 넣는 순간 켜지는 것은 빈 칸뿐 — 보고서 · 열람 기록 · 추천은 0(대표가 보고서를 발행하거나 추천을 올려야 고객 화면에 뭔가 생긴다).
3. 확인(읽기만, 넷 다 붙여도 되고 하나씩도 된다): `verify_after_0033.sql` 1~6 · `verify_after_0034.sql` 1~4 · `verify_after_0035.sql` 1~3 · `verify_after_0036.sql` 1~6 이 모두 **'좋음'**.

로컬 연습: `qa:db` 의 `scripts/db-local/run-growth-bundle.sh` — 운영 모양(0032 까지) DB 에 SQL Editor 처럼 한 덩어리로: 세 개 묶음 16 · 네 개 묶음 16 · 예전 묶음 뒤 네 개 묶음 1(아래 §7).

## 3. 되돌리기(문제가 보이면 · 1분)

- Supabase › SQL Editor 에 `supabase/manual/rollback_0033.sql` 실행 → 마지막 줄 `false | false | false`.
  하는 일: 0033 함수 11개 실행 권한 · 두 표 읽기 권한만 거둔다. **표 · 보고서 · 열람 기록 · 함수 본문은 지우지 않는다.**
  두 앱은 그 순간부터 새 칸을 숨기고 예전 화면 그대로(앱을 되돌릴 필요 없음).
- 다시 켜기 = 0033 파일 통째로 다시 실행(기록은 그대로 돌아온다 — W11d). 셋 다 되돌렸으면 묶음 `apply_0033_0035_all.sql` 을 다시 붙여도 된다(권한이 돌아오고 넣은 때 그대로 — run-growth-bundle ⑧).
- (D-685) 결과 자료 열람만 끄기: `supabase/manual/rollback_0034.sql` → 마지막 줄 `false | false`. 다시 켜기 = 0034 파일 다시(넣은 때 · 기록 그대로 — W17h · i).
- (D-686) 고객 '새 결과 자료' 표시만 끄기: `supabase/manual/rollback_0035.sql` → `false | false`. 다시 켜기 = 0035 파일 다시(W18f · g).
- (D-689) '담당자가 추천해요' 만 끄기: `supabase/manual/rollback_0036.sql` → `false | false | false`(함수 넷 실행 · 두 표 읽기 권한만 거둠 · 추천 · 관심 기록은 그대로). 다시 켜기 = 0036 파일 다시(W19n · o).
- 앱 코드까지 되돌려야 하면: OS 는 main 의 D-681 커밋을 되돌리는 새 커밋(강제 push 금지) · 홈페이지도 같은 방식.

## 4. 대표 · 팀장의 하루(쓰는 법)

1. **오늘** 머리 줄의 **'고객 화면 챙길 것 n'** 칩 → 업체마다 한 줄(가입 안내 뒤 3일 · 첫 방문 없음 3일 · 보고서 안 열어 봄 3일 · 경과 보고 14일 공백 · 30일 안 오심) → 누르면 그 업체 고객 플랫폼 탭.
2. 업체 상세 › **고객 플랫폼** 탭 → [보고서 만들기] → 종류 · 기간 → [초안 만들기] → 줄 켜고 끄기(내부 글은 꺼진 채) · 한마디 → [고객 화면으로 보기] → [고객 화면에 발행] → **안내 문구 복사 → 카톡으로 보냄**(앱은 보내지 않는다).
3. 다음 날 같은 탭에서 계정마다 '열어 봄 · 확인' 을 본다. 안 열었으면 3일 뒤 오늘 칩에 뜬다. 고객 문의는 같은 탭 '고객이 보낸 요청' 에.
4. 잘못 적었으면 [정정](고친 곳 한 줄 — 고객에게 보임) · 내려야 하면 [내리기](까닭은 내부에만).
5. (D-684) 계약 칸에 **끝나는 날**을 적어 두면 끝나기 30일 전부터 오늘 '안부 챙길 계약 고객' 에 재계약 줄 · 고객 화면 줄에 '재계약 전 연간 보고' 가 뜬다 →
   [열기] 로 연간 보고 창이 바로 열림 → 발행 · 안내 문구 → 재계약이 정해지면 [재계약했어요](새 끝나는 날).
6. (D-689) 같은 탭 **'고객에게 추천'** → [추천 고르기] → 맞는 공고 · 먼저 제안할 것 가운데 하나(또는 [직접 적기]) → 제목 · 근거 한 줄 · 마감 · 공고 주소 고치기(금액 · 점수는 막힘) →
   [고객 화면에 올리기](업체마다 3개까지) → 고객 홈 '담당자가 추천해요'. 고객이 [관심 있어요] 를 누르면 오늘 '고객 화면 챙길 것' 맨 앞에 '… 추천에 관심 있다고 하셨어요 — 연락드려 주세요' →
   연락한 뒤 탭의 [연락했어요](업체 기록의 안부 연락 날) → 줄이 빠진다. 더 안 보이게 하려면 [내리기](기록은 남음).
7. 보내기 전 · 보낸 뒤 고객이 실제로 무엇을 보는지 — 사용자 메뉴(또는 설정) '보는 화면' **[고객 화면]** → 업체 고르기 → 홈 · 프로젝트 · 보고서를 고객 계정마다 그대로(기록 0 · 대표만 · D-683). 맨 위 띠 [대표로 돌아가기].

## 5. 시범 고객 3~5곳에 붙이는 법

1. 고객에게 홈페이지 회원가입을 부탁한다 — 업체 상세 › 고객 플랫폼 › **[가입 안내 문구]** 복사 → 카톡 → **[보냈어요]**(3일 지나도 연결이 없으면 오늘 칩에 뜬다).
2. 고객이 가입하면 그 이메일로 **[연결]** — 대표(full)만 연결할 수 있다. 같은 회사 직원이 따로 보려면 그 사람 이메일로 한 번 더 연결(계정마다 기록이 따로).
3. 고객에게 보이는 단계 · 프로젝트명 확인 → 첫 경과 보고 발행(지난 2주 또는 올해) → 안내 문구 전송.
4. 첫 주: 고객이 '열어 봄 · 확인' 했는지 · 문의가 들어오는지 본다. 고객이 끊고 싶어 하면 그 계정 줄 [잠시 멈춤] · [연결 끊기] — 서버가 그 순간부터 막는다.
5. 고객 쪽 말: "보고서 아래 [확인했어요] 는 읽었다는 표시예요. 계약 검수나 대금 승인이 아니에요."

## 6. 승인이 필요한 것(대표만)

- 운영 DB 에 0033 ~ 0036 넣기(위 §2 — 묶음 한 장) · main 병합 두 곳 · 시범 고객 선정 · 고객에게 보내는 첫 안내.
- 알림톡 · 메일 자동 발송(비용 · 외부 발송) — P1 이후 따로 묻는다.

## 7. 묶음 로컬 연습(D-687 · D-689 · `scripts/db-local/run-growth-bundle.sh` · `qa:db` 안 — 세 개 묶음 · 네 개 묶음 같은 차례로)
