# 고객성장관리(My MIRAE) — 실행 계획 · 진행 상태 (D-681)

> 목표: 새 서비스를 만들지 않고, 이미 있는 **내부 OS ↔ 홈페이지 고객 화면(My MIRAE)** 을 한 줄로 이어
> "직원이 한 일 → 고객이 본다 → 고객이 반응한다 → 직원 할 일로 돌아온다" 를 서버 기록으로 닫는다.
> 상태 말: DESIGNED(설계만) · IMPLEMENTED(코드 있음) · TESTED(로컬 시험 통과) · STAGING_VERIFIED · PRODUCTION_VERIFIED.
> 이 저장소는 별도 스테이징이 없다(Preview 는 운영 DB 를 본다) — 그래서 이번 작업의 최고 단계는 **TESTED**(로컬 PostgreSQL + PostgREST 진짜 RLS 위 두 앱 통합 시험).

## 3. 지키는 것

- DB 변경은 추가만(0033 하나 — 표 2 · 함수 11 · 트리거 · 정책). 예전 마이그레이션 · 6단계 · 고객 함수 · 고객 링크 · 로그인 · 홈페이지 주소 · 디자인 그대로.
- My MIRAE 고객에게 내부 OS 작업공간 · 구독 고객 권한을 주지 않는다(연결 = 0006 표 한 줄 · full 만 만든다).
- 서버가 막는다(화면 숨김이 아님) — 남의 연결 · 남의 보고서 · 멈춘 연결 · 다른 작업공간 · 허락 없는 팀장 작업공간 · 로그인 안 한 사람.
- 실제 고객 견본을 넣지 않는다 · 견본 숫자를 실제 업체 화면에 보이지 않는다 · 규칙 계산을 AI 라 부르지 않는다.
