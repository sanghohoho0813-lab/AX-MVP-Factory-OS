### 27-2b. 엑셀 판독기 — 남이 만든 파일로 한 번 더

시험 안에서 만든 xlsx 만으로는 "우리가 쓴 것을 우리가 읽었다" 에 그친다. 그래서 **독립 라이브러리(openpyxl)가
만든 진짜 엑셀**을 한 벌 만들어 같은 판독기로 읽어 보았다(그 라이브러리는 이 작업 세션에만 설치했고 저장소에는 넣지 않았다).

```
시트: 가입자명부 / 비고            ← 시트 이름 그대로
사업장명  한솔테크(주)              ← 머리글 밖의 값도
연번 성명 주민등록번호 자격취득일 보수월액
1  김철수  900101-1234567  2026-01-15  3200000   ← 날짜 칸(엑셀이 숫자로 저장)이 날짜로
3  이영수 & 김 …                    ← XML 기호(&)도 제대로
```

### 27-3. QA 가 잡아낸 것

1. **세금 계산기를 업체에서 열면 막다른 길이었다.** '이 업체로 도구 열기' 는 쓸 수 있는 도구를 전부 보여 주는데,
   세금 계산기에만 붙이기 단추가 없었다. 업체 띠는 뜨는데 결과를 붙일 데가 없다. 계산 결과를 그대로 요약으로 만들어
   같은 단추를 달았다(퇴직급여·상속세 등 9종 전부).
2. **다시 판정하면 옛 기한이 달력에 함께 남았다.** 입사일을 고쳐 다시 붙이면 회차 날짜가 두 벌이 된다.
   같은 도구·같은 이름의 결과를 다시 붙이면 **먼저 붙였던 기한만 달력에서 내린다**(옛 결과 자체는 기록에 남는다).
3. **발행 계약 시험이 처음에는 저장소를 훔쳐보려 했다.** node 에는 `window` 가 없어 저장이 메모리 대체소로 가서
   아무것도 안 보였다. 저장 자리를 들여다보는 대신 **'고객이 보는 목록'** 을 읽도록 고쳤다 — 시험이 더 정확해졌다.
4. **엑셀 명부 시험이 필드 이름을 틀렸다**(`joinDate`·`birth` → `hireDate`·`birthDate`). 화면이 아니라 시험이 틀렸다.
   고친 뒤 주민번호 원본이 결과 어디에도 없다는 것까지 같은 시험에서 본다.
5. **붙이기 부품이 틀 밖에서 쓰이면 조용히 빈 목록이 될 수 있다.** 기본값을 로컬 모드에서 동작하게 두고,
   도구 라우트가 전부 틀로 감싸졌는지는 E2E 가 본다(390 폭 `?client=` 경로 포함).

### 27-4. 확인하지 못한 것 · 남는 한계

- **오래된 엑셀(.xls, 2003 이전) · 암호가 걸린 엑셀 · 값 없이 수식만 저장된 파일**은 읽지 못한다.
  그때는 "CSV 로 저장해 주세요" 안내가 그대로 나간다.
- 엑셀 날짜는 **엑셀과 똑같이** 1900 윤년 버그를 따른다. 1900년 1~2월 날짜는 하루 어긋날 수 있다(명부에는 없는 날짜다).
- **프로덕션에서 실제 고객 계정으로 발행해 보지 않았다.** 외부로 나가는 일이라 하지 않았다 —
  로컬 모드로 실제 발행해 '요약만 나간다' 까지 시험으로 확인했다.
- **홈페이지 크레탑 카드는 그대로 둔다.** 조사해 보니 그 주소는 고객 화면에 노출되지 않는다(권한 확인 뒤에만 건넨다).
  바꿀 SQL 은 `supabase/homepage_tools_catalog.sql` 에 실행하지 않은 채로 있다. 카드를 내리려면 홈페이지 코드도 함께 고쳐야 한다.
- 도구 기한은 **붙인 시점의 계산**이다. 법이 바뀌거나 입사일이 바뀌면 다시 판정해 붙여야 한다(그때 옛 기한은 내려간다).
- 프로덕션 화면 스크린샷은 로그인이 필요해 찍지 못했다. 배포 확인은 배포된 번들 문자열로 한다.
