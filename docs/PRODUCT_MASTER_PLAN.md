## 0. 이 문서를 쓰는 법 — 반복 개발 운영체계

대표가 **"마스터 계획 기준으로 다음 단계 고도화해 줘"** 라고 하면:

1. **읽기** — 이 문서 §7(진행판) · §9(다음 작업) → 벤치마킹 기준서의 해당 절 → `CLAUDE.md` → 최신 `main` 의 실제 코드(그 항목이 지금 어떤지).
2. **고르기** — 미완료 중 가장 중요한 **한 묶음**. 고르는 순서:
   1. 데이터 손실 · 보안 · 고객 간 노출 문제(발견되면 단계와 상관없이 먼저)
   2. P0-1 → P0-2 → P0-3 → P1(업무 연결) → P1(팀) → P2
   3. 같은 단계 안에서는 **매일 쓰는 화면 · 작게 검증 가능한 것** 먼저
   4. 🚨 승인이 필요한 항목은 질문만 올리고(보고 맨 위), 답을 받기 전에는 그 다음 항목을 한다
3. **만들기** — 기존 코드 재사용 먼저(§3). 새 원본(같은 고객 · 서류 · 업무 · 브랜드의 두 번째 저장소)을 만들지 않는다.
4. **확인하기** — `CLAUDE.md` 빠른 점검 + 고친 화면의 e2e + 스크린샷 눈 확인. 로그인 · 권한 · DB · RLS · `api/` · 저장 방식을 건드리면 `qa:db` + `qa:pilot` 도.
5. **기록하기** — `docs/DECISIONS.md` 에 D-번호 한 절 · 이 문서 §7 진행판 줄 갱신 · 필요하면 `CLAUDE.md` QA 줄.
6. **반영하기** — 빠른 점검 녹색 → `main` fast-forward → Production 에서 새 표지가 보이는지 확인(빠른 모드 · `CLAUDE.md`).
7. **보고하기** — `변경 기능 / 사용자 효용(BEFORE → AFTER) / 변경 파일 / 테스트 실제 결과 / 미검증 · 남은 위험 / 다음 단계` 만 간결히.
   대표 확인이 필요한 것은 보고 **맨 위**에 `🚨🚨🚨 [확인 필요]`.

**한 번에 로드맵 전체를 만들지 않는다.** 한 회차 = 검증 가능한 작은 묶음 하나(+ 그 화면의 작은 UI/UX 다듬기).

**먼저 대표 승인이 필요한 것(코드 작성과 운영 적용을 구분해 보고):**
운영 DB · 권한 체계(RLS · 등급) 변경과 적용 · 결제 · 과금 · 고객 데이터 삭제 · 외부 API 추가와 그 비용 · 운영 보안 정책 ·
기존 기능 삭제 · 잘 만든 것 통째로 갈아엎기 · 팀장에게 다른 AI 회사 · AI 작업실 열기 · 세금 계산기 식(D-341).

## 1. 제품 비전 · 1차 판매 범위

**비전:** 중소기업 · 정책자금 컨설턴트가 **매일 아침 여는** 프리미엄 SaaS. "고객사 하나를 중심으로 상담 · 서류 · 일정 · 마케팅이 이어지고,
초보 컨설턴트도 첫날부터 전문가처럼 일하는 곳". 기능이 많은 프로그램이 아니라 **구독료를 낼 이유가 분명한 프로그램**.

**첫 판매 고객:** 개인 컨설턴트 · 소규모 팀(사업단).

**1차 유료 상품 = 네 영역만 전면에:**

| 영역 | 고객이 얻는 것 | 지금 OS 의 자리 |
|---|---|---|
| 마케팅 · 브랜딩 | 내 브랜드 기준으로 이번 주 주제 → 스레드 · 짧은 영상 · 긴 영상 · 블로그 글 → 저장 · 이어 쓰기 · 올릴 날 · 성과 기록 | `/marketing` (대화창 첫 화면 D-511) · 고객 계정은 서버 허용 시 레이더 · 스레드 · 릴스만(`src/config/pilotMarketing.ts`) |
| 고객사 운영 | 업체 기록 · 상담 이력 · 진행 상태 · 다음 할 일 · 후속 연락 | `/ops/clients` · `/ops/clients/:id` |
| 서류 | 안전한 보관 · 자동 분류 · 글자 인식 · 누락 · 유효기간 · 요청 문구 | 업체 상세 › 서류함(비공개 보관함 `client-documents`) |
| 일정 · 업무 | 오늘 할 일 · 상담 약속 · 마감 · 놓치면 끝나는 기한 | `/` 오늘 · `/ops/calendar` · `/ops/decide` |

**보존 · 추가 구독으로 나중에:** 특허 · 벤처 · 정책자금 심화 판정 · 세무/재무 계산기 · 고용지원금 · 연구소 · AX 스튜디오 등 전문 모듈 —
코드 · 데이터는 그대로 두고, 완성도 검증 뒤 모듈별 추가 구독(`src/services/entitlements.ts` · `src/config/productCatalog.ts` 의 잠금 계산 재사용).
**카드뉴스는 1차 상품에서 고객에게 보이지 않는다**(`src/services/marketing/persona.ts` mkText 가 지운다 — 대표 화면은 그대로).

**하지 않는 것(1차):** 건설 · 공사 공정 · 근태 · 급여 · 원가 · 은행/회계 실시간 연동 · 전사 메신저 · 전자결재 · 외부 MCP 공개.

## 5. 기준 — UX · 데이터 연결 · 권한 · 보안 · QA

### UX
- **첫 화면은 단순하게**(`CLAUDE.md` 📐): 한 화면에 한 가지 일 · 맨 위에 무엇을 하는 곳인지 + 1 → 2 → 3 · 결과는 한 번 누르거나 한 번 입력하면.
- **완료 중심**: 메뉴 찾기가 아니라 일을 끝내기까지의 클릭 · 입력 수를 잰다. 핵심 업무 3클릭 안 착수가 목표 — 실측 없이 달성이라고 쓰지 않는다.
- 쉬운 한국어 · 같은 설명 세 번 반복 금지 · 자세한 이유는 접어서. 마케팅은 60대 이상 기준(D-507).
- 박스는 흰 바탕 + 얇은 회색 테두리 · 보라는 AI 단추만 · 한쪽 테두리 금지(D-370 · D-483) · 누를 수 있는 것은 손가락 + 호버(D-500).
- 상태 안내: 빈 화면 · 저장 중 · 저장됨 · 저장 실패 · 권한 없음 · 구독 만료 · AI 한도 초과를 화면마다 분명히.
- 390px 가로 넘침 0 · 누르는 곳 44px · 큰 글자에서 정상.

### 데이터 연결
- **한 번 입력한 정보는 다시 묻지 않는다** — 업체 기록 · 사실 창고(`customerFacts`)가 원본, 모듈 · 문구 · 진단서가 읽어 쓴다.
- 같은 고객 · 서류 · 업무 · 브랜드 프로필의 원본은 하나(SSOT). 새 칸은 기존 원본의 선택 칸으로.
- AI · 글자 인식 · 추정 값은 **사용자 확인 전에는 사실로 확정하지 않는다**(확인할 것 · 첫 확인 D-492). 규칙 계산을 'AI' 라고 부르지 않는다.
- 고객 비공개 자료를 공개 콘텐츠 · 외부 응답 · 다른 팀 화면에 넣지 않는다.

### 권한 · 보안
- 대표 · 내부 팀장 · 구독 고객 기능 분리 · 작업공간 RLS · 고객 플랫폼은 `portal_*` · 고객 안전 RPC 만.
- 키는 서버 환경변수에만(`VITE_` 금지) · 브라우저는 AI 공급자를 직접 부르지 않는다 · AI 지시문 비공개 규칙(D-264 · `api/_ai/guard.js`).
- 주민등록번호 · 공동인증서 비밀번호 저장 금지 · DB 변경은 추가만.

### QA
- 회차마다: `npx tsc --noEmit -p tsconfig.app.json && npx oxlint src && npm run build` · `npm run test:all` · 고친 화면의 e2e · 스크린샷 눈 확인.
- 로그인 · 권한 · DB · RLS · `api/` · 저장 방식을 건드리면 `qa:db` + `qa:pilot`.
- 대표 신호("전체 점검 돌려")에는 `CLAUDE.md` 병합 전 QA 전부.
- 보고에는 단위 · e2e · RLS · 실계정 중 무엇을 했고 무엇을 못 했는지 적는다.
