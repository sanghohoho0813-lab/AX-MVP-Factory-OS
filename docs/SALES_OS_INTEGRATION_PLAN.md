# 기업컨설팅 OS → 미래AI랩 운영 OS 영업 통합 계획 (초안 · 2026-09-26)

> 대상: 도입 검토중 '영업 도구 모음'(`/tools/sales-kit`) — 원본 `corp-consult-sales-os` main `App.jsx`(법인컨설팅 세일즈 OS).
> 지금 코드: `src/tools/salesKit/orig/SalesApp.jsx` 5,560줄 · 14화면. 저장은 모듈 기록 `sales-kit`(업체당 한 줄 `accounts` + 공용 `orig`).
> 이 문서는 범위 · 추천안이다. 대표가 결정할 것(§6)이 정해지면 단계별로 구현한다.

## 1. 지금 상태 — 무엇이 문제인가

- 영업 도구는 **자기 고객 기록을 따로** 갖는다. 고객 관리 업체와 이어지긴 하지만 **한 방향**(이름·연락처만 가져옴).
  영업 쪽의 단계 · 다음 연락일 · 메모는 고객 관리 · 오늘 · 일정에 **안 보인다**.
- 그래서 같은 일을 두 번 한다: 고객 목록 2개 · 다음 연락 2개 · 할 일 2개 · 파이프라인 2개 · 성과 화면 2개.
- 검토중 안내문(`ToolsReviewPage.tsx` WHY)은 "고객 관리·파이프라인·할 일은 안 가져왔다" 고 적혀 있지만 D-93 부터 원본 전체가 돈다 — **사실과 다름**.
- 크레탑 추출기가 원본 안에 한 벌 더 있다(이미 크레탑 분석기에 있음).

## 2. 원칙

1. **고객 기록은 하나** — 고객 관리(`ClientOpsRecord`)가 유일한 고객 장부. 영업 정보는 그 안에 `sales` 칸으로 더한다(클라우드는 `payload jsonb` 라 **DB 변경 없음**).
2. **계약 전 고객도 1급 시민** — 잠재고객 → 미팅 → 제안 → 계약 / 보류 / 실패를 고객 관리 안에서 본다. 계약이 안 돼도 기록은 남는다.
3. **엔진은 가져오고, 화면은 다시 짠다** — 점수 · 전략 추천 · 미팅 대본 · 상품표 같은 규칙 엔진은 그대로 옮기고, 화면은 OS 모양(카드·테마·휴대폰)으로 새로 만든다. 규칙 계산은 'AI' 라고 부르지 않는다.
4. **다음 연락 · 할 일 · 성과는 OS 에 있는 곳으로** — 새 화면을 만들지 않고 오늘 · 일정 · 성과 지표에 합친다.

## 5. 단계

| 단계 | 내용 | 대표가 겪는 변화 |

## 6. 대표가 정할 것

1. 월납 보험료 제안 기능을 쓰는가? (쓰면 3단계 상품·견적에 선택 항목으로)
2. 대표가 만들고 있는 'AX 1차 미팅 체크리스트' 프로그램 — 2단계 미팅 준비를 먼저 만들고 나중에 합칠지, 기다릴지
3. 운영(클라우드)의 영업 도구 모음에 실제로 쌓인 고객 기록이 있는가 (옮기기 범위)
4. 상품 가격표 40종 · 수임료 범위가 지금 가격 정책과 맞는가
5. 잠재고객도 '고객 관리' 옆 숫자(고객사 수)에 셀지, 계약 고객만 셀지
