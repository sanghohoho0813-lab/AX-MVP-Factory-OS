# 기업인증 모듈 (D-170)

기업성장 › 기업인증(`/tools/cert-os`). 업체 하나를 열면 벤처 · 기업부설연구소 · 이노비즈 · 메인비즈 · ISO 가운데
**무엇을 · 왜 · 지금 · 무엇을 준비해서** 할지 — 준비도 5단계와 근거 · 자가진단 · 실사 대비 · 갱신까지.

## 1. 구조 — Core 와 OS 연결층 분리

```
src/certification/
  core/         판정 · 준비도 5단계 · 혜택 고르기 · 진행 순서 · 자가진단 엔진 · 실사 대비 엔진 · 설명 문구 (OS 를 모른다)
  rules/        공식 기준 데이터(출처 · 고시 번호 · 시행일 · 마지막 확인일 · 확인 못 한 것) — 규정이 바뀌면 여기만
  innobiz/      이노비즈 준비 점검 문항 · 실사 예상 질문(도메인 규칙)
  mainbiz/      메인비즈 준비 점검 문항 · 실사 예상 질문(같은 엔진, 다른 규칙)
  iso/          ISO 9001 · 14001 · 45001 검토 판단 · 상담 요청 요약
  integration/  MIRAE OS 어댑터 — 업체 기록 → CertificationClientContext · 모듈 기록 저장 · 맞춤 추천 한 줄
  ui/           화면(OS 의 Badge · Button · Surface · t-* 글자 · 색 토큰만)
  __tests__/    npm run test:cert (Core 가 OS 를 import 하지 않는지도 시험)
```

- Core → OS import 0(시험으로 지킴). 떼어 쓰려면 `core · rules · innobiz · mainbiz · iso` 를 복사하고 `CertificationClientContext` 만 채워 주면 된다.
- 입력 `CertificationClientContext`(업력 · 업종 · 직원 · 재무 · 연구조직 · 특허 · 보유 인증 · 계획 · 증빙) → 결과 `CertificationAssessment`(추천 · 준비도 · 한 줄 이유 · 근거 · 모자란 사실 · 모자란/있는 증빙 · 혜택 · 타이밍 · 다음 행동 · 갱신).

## 2. 준비도 · 추천

- 자체 준비도는 **매우 높음 · 높음 · 보통 · 낮음 · 매우 낮음 · 추가 확인 필요** 뿐. 퍼센트 · 자체 점수 없음. 등급마다 근거(✓ △ ✗ ?)가 붙는다.
- 반드시 필요한 조건(중소기업 · 업력 3년 · 제외 사유 · 부채비율 1,000% · 완전자본잠식 · 제외 업종)이 ✗ 면 매우 낮음, 모르면 추가 확인 필요.
- 공식 점수(이노비즈 자가진단 650 · 현장 700 + B등급 / 메인비즈 600 · 700)는 '공식 기준' 칸에만 숫자로. 자체 판정과 섞지 않는다.
- 추천: 보유 중 · 지금 추천 · 진행 가능 · 보완 후 추천 · 아직 이르다(가능해지는 달) · 우선순위 낮음 · 지금은 굳이 필요 없음 · 추가 확인 필요 — 한 줄 이유와 함께.

## 3. 공식 기준 관리(Freshness Gate)

`rules/officialRules.ts` — 인증마다 출처 URL(법제처 · 이노비즈넷 · 중소벤처24 · ISO · KAB) · 고시 번호 · 시행일 · 마지막 확인일(2026-10-07) · 확인 못 한 것.
마지막 확인에서 180일이 지나면 화면이 '최신 기준 확인 필요' 를 띄운다.

2026-10-07 확인 결과 중 눈여겨볼 것:
- 기업부설연구소: 2026-02-01 부터 「기업부설연구소등의 연구개발 지원에 관한 법률」.
- 이노비즈 · 메인비즈: 2026-06-22 부터 최근 3년 체불 명단 · 산재 공표 · 공정거래 시정명령 · 보조금 참여제한도 제외 사유.
- 메인비즈 자가진단 통과선은 600점(650 아님).
- ISO 9001:2026(2026-09-16) · ISO 14001:2026(2026-04-15) 발행.
- 확인 못 한 것: 이노비즈 지표 이름 · 배점(비공개), 메인비즈 평가 영역(공식 안내 두 곳이 다름), 메인비즈 연장 기간, 벤처 업종별 연구개발비 비율 표, 연구소 시행규칙 세부.

## 4. Facts · 서류 재사용

어댑터가 사실 창고(업력 · 업종 · 직원 · 재무 · 보유 인증 · 연구소 · 특허) · 회사 정보 '인증서' 칸(서류에서 읽은 인증 · 유효기간) · 서류함(받음 · 만료)을 읽는다.
기록에 없는 것만 '업체 사정 확인' 칩으로 묻는다(타이핑 없음, 모듈 기록 `cert-os/profile` 에 업체별 저장).
이미 있는 자료는 '이미 있는 자료' 로 보이고 준비서류 요청 문구에서 빠진다.

## 5. 실사 대비

이노비즈 · 메인비즈 3단계 '실제 진행' 에서 [자가진단 시작] → 한 질문씩(기록으로 미리 고른 답과 근거 · 필요한 증빙 · 있는 증빙 · 판정) →
결과(5단계 · 강점 · 보완 · 대표 확인 · 실사 전에 준비할 자료 + 공식 기준) → [실사 대비 시작] → 예상 질문 하나씩(의도 · 기록 · 증빙 · 답변 초안) →
[이대로] [고치기] [대표 확인 필요] → 모의 실사 결과(점수 없이 5단계 · 강점 · 보완 · 실사 전 반드시 확인).
근거가 없으면 초안을 만들지 않고 '대표 확인 필요'.

## 6. ISO

ISO 9001 · 14001 · 45001 을 업종 · B2B · 조달 · 수출로 검토 추천 / 굳이 필요 없음. [김상호 대표에게 상담 요청] → 업체 기록 활동에 남기고
업체명 · 업종 · 직원 수 · 관심 ISO · 보유 자료만 담은 문구를 복사(연락처 · 번호 없음). 인증은 KAB 인정 인증기관이 한다고 적는다.

## 7. 남은 것(P1 · P2)

- 벤처 · 연구소 판정을 기존 화면(특허+벤처 · 연구소 관리)의 결과와 서로 잇기(지금은 기존 화면으로 보내기만).
- 업체 사정 칩에서 고른 사실(연구소 · 특허)을 사실 창고에 '확인' 으로 되돌리기(지금은 모듈 기록에만).
- 인증 받은 뒤 인증번호 · 최초 인증일 · 사후심사 일정을 따로 적는 칸.
- 메인비즈 평가 영역 · 연장 기간 공식 원문 확인 뒤 문항 손질.
- AI 어댑터: `explainFor` · 실사 초안 입력(판정 · 업체 사정)을 그대로 넘기는 자리.
